# Developing Webjet

How the code is organized, how to build and test it, and the conventions and
pitfalls that aren't obvious from the code. The design itself is in
[webjet-architecture.md](webjet-architecture.md); section numbers (§) in code
comments refer to it.

## Workspace

| Crate | Depends on | Notes |
| --- | --- | --- |
| `webjet-proto` | | FlatBuffers types, generated by planus. |
| `webjet-core` | proto | Pure, deterministic logic: no I/O, no clocks except where passed in. |
| `webjet-net` | core, proto | Transports. Feature `anytls` (default) pulls in BoringSSL. |
| `webjetd` | core, net, proto | The agent (library + binary). Feature `anytls` forwards to `webjet-net`. |
| `webjet-tools` | webjetd, core, net, proto | `webjetctl`, `webjet-root`, `webjet-signer`; also the shared account-key code (`Account::unlock`, `sign`). |
| `webjet-app` | webjetd, tools, core, proto | GPUI desktop app. `model` and `client` are GUI-free and unit-tested; `ui` is the GPUI front end. |

Edition 2024, `rust-version = "1.88"`.

## Building

```sh
cargo build --workspace                       # needs cmake and Go for BoringSSL
cargo build --workspace --no-default-features # without AnyTLS: no C toolchain needed
```

BoringSSL makes the first build slow (several minutes). For quick iteration on
code that doesn't touch AnyTLS, use `--no-default-features`.

## Checks before committing

```sh
cargo fmt
cargo clippy --workspace --all-targets
cargo clippy --workspace --all-targets --no-default-features
cargo test --workspace
```

All of them must be clean: the workspace has no clippy warnings, including in
tests.

- **No `unwrap()`/`expect()` outside tests.** The workspace lints warn on
  `clippy::unwrap_used` and `clippy::expect_used`; `clippy.toml` allows them
  in tests. Parse untrusted bytes with the checked readers in
  `webjet-core/src/bytes.rs`, which return `None` on short input, and drop
  bad packets instead of panicking. Sort floats with `total_cmp`.
- The generated FlatBuffers module is exempt (`#[rustfmt::skip]` and lint
  allows in `webjet-proto/src/lib.rs`). Don't edit `generated.rs` by hand.
- Some code is compiled only on one OS (`cfg(target_os = "linux")`,
  `cfg(windows)`). Clippy on macOS doesn't see it, so check the other targets
  too when you touch platform code:
  - Linux: `docker run --rm -v "$PWD":/src -w /src rust:1-bookworm cargo clippy --workspace --exclude webjet-app --all-targets` (or build the Docker image). `webjet-app` is left out because GPUI needs X11/Wayland and Vulkan development packages that the plain Rust image doesn't have.
  - Windows: `cargo xwin clippy --target x86_64-pc-windows-msvc -p webjetd -p webjet-tools --no-default-features`.

## Wire formats

Schemas are `crates/webjet-proto/schema/webjet.fbs` (signed objects, tree
leaves) and `wire.fbs` (hop messages, RPC, Raft). After editing them, run
`crates/webjet-proto/regen.sh` (needs `cargo install planus-cli --version
1.3.0`) and commit the regenerated `src/generated.rs`.

- planus 1.3 has no fixed-size arrays in structs, so 32-byte keys, 64-byte
  signatures, 16-byte ids and CIDRs are structs of little-endian `u64` words
  (`b0..b3`) with the same byte layout.
- Only **append** fields to tables, never reorder or remove them: older nodes
  must still decode new messages (§15.7). New union variants go at the end.
- Signed objects are envelopes: `type || body`, signed with Ed25519 over a
  context string per message type (`webjet-proto` message-type registry).

## The controller state machine

`webjet-core/src/statemachine.rs` applies committed log entries. It must be
deterministic: every controller computes the same tree from the same log
(§15.5).

- No wall clock: use the entry's `timestamp`.
- No randomness: use the entry's `random` fields, chosen by the leader when
  it prepares the entry.
- Only ordered maps (`BTreeMap`/`BTreeSet`) where iteration order matters.

The leader *prepares* an entry: it fills in the timestamp, the random values
and the resulting leaf bytes. Followers recompute the leaves and halt on any
difference, so a bug that makes replicas disagree shows up as a halted
follower, not as silent divergence.

## Raft

`webjetd/src/controller/raft.rs` is a pure state machine: time is passed in,
randomness comes from a seeded RNG, storage can be in memory. Pre-vote,
check-quorum, single-server membership changes tracked from the log
(`classify_entry` in `controller/mod.rs`).

Testing it:

```sh
cargo test -p webjetd --lib raft                                          # ~1 min
WEBJET_RAFT_SEEDS=2000 cargo test --release -p webjetd --lib randomized   # soak
WEBJET_RAFT_STATS=1 WEBJET_RAFT_TRACE=1 ...                               # per-seed stats / seed being run
scripts/raft-mutations.py                                                 # ~10 min
```

`raft_tests.rs` has targeted scenarios and a simulator. The simulator injects
crashes, restarts, partitions, message loss, duplication, reordering,
snapshots and membership changes, checks the Raft safety properties after
every step, and checks liveness once faults stop.

`scripts/raft-mutations.py` re-introduces ten classic Raft bugs one at a time
and fails if the tests miss one. Run it after changing `raft.rs` or the
tests. Its patterns match the source with any whitespace; if a refactor
changes the code it looks for, it reports a setup error (exit status 2) and
the pattern must be updated.

When a randomized run fails, rerun the failing test with
`WEBJET_RAFT_TRACE=1` to find the seed, then reproduce with that one seed.
Every failing seed so far has been a real bug or a test-harness bug (for
example, waiting for a value whose leader was deposed), never noise.

## Locking

The agent shares state between many tasks; deadlocks have been the most
common bug. Rules:

- Never call a function that takes a lock while holding another lock it
  might take. Clone what you need, drop the guard, then call. Especially:
  `Node::records`, `Node::hops`, the store, a session's `inner`, and
  `Node::circuits`.
- `Node::store.read()` is recursive (`read_recursive`), so nested reads are
  fine, but never take `write()` while holding a read.
- Never hold a `parking_lot` guard across `.await`.
- Helpers that iterate over all sessions or hops (e.g. counting handshakes in
  progress) must not run while the caller holds one of them; take the count
  first.
- In edition 2024 a temporary in an `if let` or a let-chain lives until the
  end of the whole `if`, *including its body*. So
  `if let Some(c) = n.circuits.lock().first() && send(c)` holds the circuit
  lock while `send` runs. Bind the value with `let` first, then test it.
  This deadlocked the e2e re-key (found by `scripts/soak-test.sh`).

`sample <pid>` (macOS) or `gdb -p <pid> -batch -ex 'thread apply all bt'`
(Linux) on a hung agent shows which locks the threads wait on.

## Tests that need more than `cargo test`

| Script | Needs | What it checks |
| --- | --- | --- |
| `scripts/local-net.sh [N]` | nothing (no root) | A full network on 127.0.0.1 by runbook 1, tun disabled. `scripts/local-net.sh stop` ends it. |
| `scripts/cluster-test.sh` | nothing | Three controllers, leader failover, writes still commit. |
| `scripts/soak-test.sh [s]` | nothing | Runs the local network past the e2e re-key interval (120 s) and checks every agent still answers. Catches timer-driven deadlocks. |
| `cargo test -p webjet-app --test live` | `scripts/local-net.sh 2` | The app's sign-in and operations against a live network (admin vs. normal account). Skipped without a network. |
| `docker/e2e.sh` | Docker, image `webjet:test` | Real tun interfaces: kernel ping, magic DNS, policy, subnet gateway. |
| `docker/deploy-test.sh` | Docker | The deployment image as documented in docs/docker.md. |
| `docker/tpm-test.sh` | Docker | TPM key sealing against a software TPM (swtpm), refusal by another TPM. |
| `docker/windows-test.sh` | Docker, `cargo-xwin`, LLVM | Windows unit tests under Wine. |

Notes:

- `local-net.sh` uses fixed passphrases from the environment
  (`WEBJET_ROOT_PASSPHRASE`, `WEBJET_ACCOUNT_PASSPHRASE`) and keys in
  `/tmp/webjet-local/keys`. Query a node with
  `target/debug/webjetctl --socket /tmp/webjet-local/node-02/control.sock status`.
- macOS has no `timeout`; use `perl -e 'alarm shift; exec @ARGV' 5 <cmd>`.
- `docker/e2e.sh` uses the `test` image: `docker build --target test -t webjet:test .`
- `docker/tpm-test.sh` sets `TPM2TOOLS_TCTI` to the software TPM and runs
  the TPM unit test with `WEBJET_TEST_TPM=1`. Without a kernel resource
  manager, every TPM operation must flush transient objects or the TPM runs
  out of slots after a few operations; the keystore does this.
- Windows: install with `cargo install cargo-xwin` and `brew install llvm`
  (for `clang-cl`/`lld-link`). `windows-test.sh` runs each test in its own
  Wine process. On Apple Silicon, Wine runs under x86 emulation, which
  sometimes crashes the emulator ("rosetta error"); those tests are counted
  as EMU, not as failures. Wintun, NRPT and the service manager need a real
  Windows machine.
- Shell scripts that create a file and run it in the same step: `chmod +x`
  first, or start them with `sh script.sh`.

## Docker image

The root `Dockerfile` has a `runtime` target (default, the deployment image)
and a `test` target (adds `ping`, `dig`, `nc` and the test scripts). Build
caches are keyed by platform. `docker/entrypoint.sh` turns `WEBJET_*`
variables into `webjetd.toml` and handles first-start enrollment; it writes
values into TOML strings, so it rejects values containing quotes,
backslashes or newlines. Everything an operator needs is in docs/docker.md.

## Platform code

`webjetd/src/platform.rs` does routes, split DNS and gateway NAT per OS by
running the system tools (`ip`, `route`, `resolvectl`, `netsh`, PowerShell
for NRPT, `iptables`). `ipc.rs` abstracts the control channel (Unix socket or
named pipe), `winsec.rs` builds Windows ACLs, `keystore.rs` the key storage
backends, `service.rs` the Windows service and signal handling.
