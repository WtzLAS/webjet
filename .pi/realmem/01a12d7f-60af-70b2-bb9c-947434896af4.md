webjet-net FEC uses reed-solomon-erasure 6.0.0 with `simd-accel` on, through the patched copy at `vendor/reed-solomon-erasure` (`[patch.crates-io]` in the root Cargo.toml and fuzz/Cargo.toml). The details are in vendor/README.md, and every change is marked `// Webjet:`.

**Why patched.** Upstream builds `simd_c/reedsolomon.c` once, with `-march=haswell` on x86_64. That build crashes with SIGILL on CPUs without AVX2. The user chose runtime dispatch over a fixed CPU level.

**What the patch does.**
- `build.rs` reads `CARGO_CFG_TARGET_ARCH`.
  - On x86_64 it compiles the C file twice, `-mssse3` and `-mavx2`, renaming the exported functions via `-D` to `reedsolomon_gal_mul{,_xor}_ssse3` and `_avx2`.
  - On aarch64 it compiles it once.
  - MSVC targets are built only when the compiler is clang-cl (cargo xwin).
  - It sets the cfgs `rse_simd` + `rse_simd_x86` or `rse_simd_neon`.
- `galois_8.rs` `kernels()` uses `is_x86_feature_detected!` to pick AVX2 > SSSE3 > the Rust code. `pub fn simd_level()` returns the choice.
- `webjet_net::fec::simd()` exposes it. webjetd logs `fec_simd` at start, and `webjetctl local status` shows `"fec_simd"`.

**Measured** (k=10 data + 3 parity, 1280-byte shards, encode GB/s): Xeon 8372HC Rust code 0.98, SSSE3 4.3, AVX2 10.4; Apple M Rust code 0.87, NEON 2.95.

**How to verify.**
- Old CPUs: copy the crate to /tmp, then `cargo test --release --features simd-accel --no-default-features`, then run the test binary under `qemu-x86_64 -cpu Nehalem|core2duo|qemu64` (apt `qemu-user` in rust:1-bookworm on 10.4.0.9).
- Windows: `cargo xwin test --no-run --target x86_64-pc-windows-msvc`, then run the exe in `scottyhardy/docker-wine:stable-9.0` with `HOME=$(mktemp -d) WINEPREFIX=$HOME/wp`.
- The test that guards the kernels is `galois_8::tests::simd_kernels_match_the_rust_code`.
- This Mac has no Rosetta, so x86_64-apple-darwin binaries can't run locally.
- `scripts/gpui-vendor-check.sh` also watches reed-solomon-erasure for new releases.
