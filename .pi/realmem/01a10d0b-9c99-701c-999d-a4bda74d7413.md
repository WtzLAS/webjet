After v0.6.0, all direct dependencies were moved to their latest majors: rand 0.10, rand_core 0.10, ed25519-dalek 3, chacha20poly1305 0.11, aes-gcm 0.11, argon2 0.6, base64 0.23, toml 1, hickory-proto 0.26, dirs 7, if-addrs 0.15, windows-sys 0.61, sha2 0.11, zip 8.

API mapping used:
- `OsRng.fill_bytes` → `rand::rand_core::UnwrapErr(rand::rngs::SysRng).fill_bytes` (needs `rand::Rng` in scope).
- `thread_rng()` → `rand::rng()`; `gen_range` → `random_range`, `gen_bool` → `random_bool` (trait `RngExt`).
- `StdRng::from_entropy()` → `rand::make_rng()`.
- `SliceRandom::choose_multiple` → `IndexedRandom::sample`.
- `rand::random::<usize>()` no longer exists; use `rand::random_range(0..n)`.
- aead 0.6: `AeadInPlace` is deprecated, so use `AeadInOut::encrypt_inout_detached(nonce, aad, buf.as_mut_slice().into())` / `decrypt_inout_detached(.., tag.try_into().ok()?)`. `Key::from(arr)`, `Nonce::from(arr)`, and `XNonce::try_from(slice)` replace `from_slice`.
- sha2 0.11 `Sha256` doesn't implement `io::Write`, so feed it with `update` in a read loop.
- hickory-proto 0.26 `Message` has public fields: `metadata` (id, op_code, recursion_desired/available, response_code, authentic_data), `queries`, `answers`, `additionals`. Build replies with `Message::response(id, op_code)`. `Record.data` is `RData`, not an `Option`. `crates/webjetd/src/dns.rs` now has the pure helpers `response_to` and `fix_forwarded`, tested with raw wire bytes.

Wire compatibility was checked with an example built against the old and the new commits: Ed25519 signatures, e2e frames, the Argon2 key-file seal, and the UDP gate all interoperate.

Remaining entries in `cargo update --verbose`'s "Unchanged" list can't be updated: gpui 0.2.2 pins `=` versions of cocoa, cocoa-foundation, core-foundation 0.10.0 and taffy 0.9.0. netconfig-rs 0.1.6 needs core-foundation 0.10.1, which conflicts with that pin. generic-array 0.14.7 is pinned by crypto-common 0.1.7. The old rand_core 0.6, windows-sys 0.59 and generic-array copies come only from gpui/oo7/rustix/winreg.

Side effect: the RNG change shifted the Raft sim timing. `prevote_keeps_a_partitioned_follower_from_disrupting` compared state-machine lengths before the last commit index reached the follower, so it now runs 1 s with no new proposals before comparing.
