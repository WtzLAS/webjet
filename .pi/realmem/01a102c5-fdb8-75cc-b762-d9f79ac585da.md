Releases: annotated tag `vX.Y.Z` (message = release description); workspace Cargo.toml version must match. `scripts/release.sh vX.Y.Z [--publish]` runs on macOS with Docker and the tag checked out: macOS aarch64/x86_64 natively, Linux aarch64/x86_64 via `docker/release.Dockerfile` (Debian 11 → glibc 2.31+), Windows x86_64-pc-windows-msvc via `cargo xwin`. Output `dist/<tag>/` (gitignored): `webjet-<tag>-<target>.tar.gz` (webjetd, webjetctl, webjet-root, webjet-signer), Windows `.zip` with the 4 .exe + wintun.dll 0.14.1 amd64 (wintun-0.14.1.zip sha256 07c25618…f51 pinned) + wintun-LICENSE.txt, all with `.sha256`. `--publish` pushes the tag, creates the Forgejo release via API (POST /repos/webj8/webjet/releases, then /releases/<id>/assets?name=…), needs `WEBJET_FORGEJO_TOKEN` (here `$VP309_FORGEJO_TOKEN`). Repo webj8/webjet on forgejo.wolf109909.top is public. Debian 11 build quirks: archived security mirror 404s (amd64 libclang pulls libc6-i386 & co. pinned to unavailable security versions → install empty stub debs), Debian cmake 3.18 < BoringSSL's 3.22 → Kitware cmake 3.31 tarball. Docker's default resolver on this Mac can't resolve forgejo.wolf109909.top: use `--dns 1.1.1.1` (`WEBJET_TEST_DNS=1.1.1.1` in docker/release-test.sh). cargo-xwin needs Homebrew `llvm` AND `lld` on PATH (`/opt/homebrew/opt/lld/bin:/opt/homebrew/opt/llvm/bin`); otherwise it symlinks `~/Library/Caches/cargo-xwin/lld-link` → rustup's `rust-lld`, which can't run standalone (missing libLLVM.dylib) and CMake deps (boring-sys, aws-lc-sys) fail the compiler check — delete that symlink and `target/x86_64-pc-windows-msvc/release/build/{boring-sys,aws-lc-sys}-*` (CMake caches the linker). v0.1.0 = commit 9bd8ae9, Forgejo release id 12 (Windows zip added later, checked only under Wine).
