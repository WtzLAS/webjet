A release is an annotated tag `vX.Y.Z` (its message becomes the release description). The workspace Cargo.toml version must match, and the install commands in README.md, scripts/install.sh and docs/webjet-operations-guide.md name the tag (Forgejo has no "latest" download URL). Published on forgejo.wolf109909.top/webj8/webjet (public repo): v0.1.0, v0.2.0, v0.2.1, v0.2.2, all built on the Mac with scripts/release.sh.

From now on releases come from CI. Pushing the tag runs `.forgejo/workflows/release.yml` on the user's linux/amd64 Forgejo runner (label `docker`) in the builder image `forgejo.wolf109909.top/webj8/webjet-builder:1` (`ci/builder.Dockerfile`): tests, re-fetch the annotated tag (actions/checkout drops it), then `scripts/release.sh <tag> --publish --targets` for x86_64-unknown-linux-gnu, aarch64-unknown-linux-gnu and x86_64-pc-windows-msvc. It publishes with the RELEASE_TOKEN repo secret, else the workflow token. macOS isn't built in CI: the user adds it from a Mac with `scripts/release.sh vX.Y.Z --publish --targets "aarch64-apple-darwin x86_64-apple-darwin"`, which uploads into the existing release and replaces same-name assets. `ci.yml` (push/PR): fmt, clippy `-D warnings` for Linux (with and without default features) and Windows, tests; webjet-app excluded. `builder-image.yml` builds and pushes the image (docker:27-cli job container, runner `docker_host: automount`, REGISTRY_USER/REGISTRY_TOKEN secrets); bump the image tag in all three workflows together. As of commit 1b2c4a4 the workflows and the image were written but never built or run.

Builder image: rust:1-bullseye (glibc 2.31); gcc-aarch64-linux-gnu cross toolchain (linker/CC/CXX/AR env vars, bindgen `--sysroot=/usr/aarch64-linux-gnu`); LLVM 18.1.8 release trimmed to clang, clang-cl, lld-link, llvm-lib, llvm-dlltool and libclang (LIBCLANG_PATH=/opt/llvm/lib, needs libtinfo5); nasm and ninja-build (cargo-xwin uses the Ninja CMake generator; BoringSSL/aws-lc need NASM for Windows); Kitware CMake 3.31; Node 20 for actions/checkout; cargo-xwin 0.23.1 with the Microsoft CRT and SDK pre-downloaded (`cargo xwin cache xwin`, XWIN_CACHE_DIR=/opt/xwin).

`scripts/release.sh <tag> [--publish] [--targets "…"]` checks tag == HEAD, clean sources and the version, then per target builds macOS natively (Mac only), Linux with cargo on Linux or in Docker via `docker/release.Dockerfile` elsewhere, and Windows with cargo-xwin. Output in `dist/<tag>/` (gitignored): `webjet-<tag>-<target>.tar.gz` (webjetd, webjetctl, webjet-root, webjet-signer), the Windows `.zip` with the four .exe files, wintun.dll 0.14.1 amd64 (download checksum pinned) and wintun-LICENSE.txt, `webjetup-<tag>-<target>[.exe]` and `install.sh`, each with a `.sha256`. `--publish` needs WEBJET_FORGEJO_TOKEN (API and repo from the origin remote, or WEBJET_FORGEJO_API / WEBJET_FORGEJO_REPO); it pushes the tag if missing, creates or reuses the release and uploads.

Debian 11 build quirks (handled in docker/release.Dockerfile and the builder image): the archived security mirror no longer serves every update (drop the security lines; on amd64 libclang pulls libc6-i386 and friends pinned to unavailable versions, replaced by empty stub packages); Debian's CMake 3.18 is older than BoringSSL's minimum 3.22, so Kitware's CMake is used.

Checking a published release: `docker/release-test.sh vX.Y.Z` and `RELEASE=vX.Y.Z docker/runbook-test.sh`.
