`webjetctl network config apply` (crates/webjet-tools/src/bin/webjetctl.rs `apply_network` → config.rs `fill_refuse_certificate` → lib.rs `refuse_certificate`): with `[transport.camouflage] mode = "refuse"` the `domain`/`certificate`/`next_certificate`/`next_spki` fields are optional and ignored (a note is printed; files never read). AnyTLS clients still pin a certificate, so apply keeps the network's current camouflage domain+certificate from the tree, or on a network without one makes a self-signed P-256 cert for a random `www.<10 letters>.com` and first submits its key with SetCamouflageSecret (empty site). Website mode requires `domain` + `certificate` (PEM file relative to the config file, or inline PEM text; `show` prints inline PEM so the shown file re-applies). Before commit 45997b1, controllers never wrote `camouflage.json` (agent.rs `secrets()` skipped controllers), so a controller with `[listen] anytls` never served AnyTLS; now it copies the secret from its own state machine. Verified with `ANYTLS=true scripts/local-net.sh 2` (AnyTLS on port+2000) and node-02 limited to anytls only (now via `webjetctl local config set transport.priority.tls 0` etc.).
