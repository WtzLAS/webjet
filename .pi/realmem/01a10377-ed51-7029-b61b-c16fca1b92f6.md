`webjetctl transport apply` (crates/webjet-tools/src/bin/webjetctl.rs `transport_apply`, lib.rs `refuse_certificate`): in `camouflage: mode: refuse` the `domain`/`certificate`/`next_certificate` fields are optional and ignored (a note is printed; files never read). AnyTLS clients still pin a certificate, so apply keeps the network's current camouflage domain+certificate from the tree, or on a network without one makes a self-signed P-256 cert for a random `www.<10 letters>.com` and first submits its key with SetCamouflageSecret (empty site). Website mode requires domain + certificate file (relative to transport.yaml). Before commit 45997b1, controllers never wrote `camouflage.json` (agent.rs `secrets()` skipped controllers), so a controller with `[listen] anytls` never served AnyTLS; now it copies the secret from its own state machine. Verified with `ANYTLS=true scripts/local-net.sh 2` (AnyTLS on port+2000) and node-02 limited to `[transport] tls=0 kcp=0 anytls=50`: hop over anytls, ping via ctl-01.
