Tree limits are u64 with no upper bound in validate.rs. `crates/webjetd/src/metrics.rs` has `limit_usize(n, name)` and `limit_u32(n, name)`, which saturate (`try_from(..).unwrap_or(MAX)`). A plain `as u32` wrapped 2^32 to 0, so e.g. `conntrack_new_per_sec` refused every flow. All conntrack/circuit/gossip/e2e callers use them. Limits take the store lock, so read them before locking a table: `dataplane::ct_limits(n)` returns a closure applied to the locked Conntrack, and `proxy::refresh` reads its limits first. Test: `metrics::tests::huge_limits_saturate_instead_of_wrapping`.
