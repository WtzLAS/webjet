Integration tests beyond `cargo test` (table in docs/development.md):
- `scripts/local-net.sh [N]` (no root; a whole network on 127.0.0.1), `scripts/cluster-test.sh` (leader failover), `scripts/soak-test.sh` (past the 120 s e2e re-key; catches timer-driven deadlocks), `cargo test -p webjet-app --test live` (needs the local net; skips otherwise).
- `docker/e2e.sh` (real tun, DNS, policy, gateway; needs `docker build --target test -t webjet:test .`), `docker/deploy-test.sh` (the deployment image as in docs/docker.md).
- `docker/webjetup-test.sh` (install.sh/webjetup on a systemd container from fake release pages), `docker/runbook-test.sh` (ops guide runbooks 1, 2, 3, 4, 6, 8, 9 on systemd containers; `RELEASE=vX PORT=8443` uses a published release), `docker/release-test.sh vX` (published release in Debian 11, Ubuntu 20.04, Debian 12 × amd64/arm64). Systemd containers need `--privileged --cgroupns=host -v /sys/fs/cgroup:/sys/fs/cgroup:rw --tmpfs /run`; they have no `ps` (use `systemctl show -p MainPID` + `/proc`).
- `docker/tpm-test.sh`: swtpm with `TPM2TOOLS_TCTI=swtpm:host=127.0.0.1,port=2321` and `WEBJET_TEST_TPM=1`; without a kernel resource manager every tpm2-tools step must `tpm2_flushcontext -t` or the TPM runs out of object slots (the keystore does this).
- `docker/windows-test.sh`: cross-builds with cargo-xwin and runs each test in its own Wine process (scottyhardy/docker-wine:stable-9.0, linux/amd64, WINEPREFIX under $HOME). On Apple Silicon, Rosetta sometimes crashes Wine ("rosetta error") → counted EMU, not failure. Wintun, NRPT and the Windows service manager have never run on real Windows.

Pitfalls: a script created and launched in the same tool batch may run before `chmod +x` or with old contents (run it separately or via `sh script.sh`); BSD sed needs `;` before a closing `}`.
