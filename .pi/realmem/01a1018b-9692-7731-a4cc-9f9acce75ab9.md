Webjet integration tests beyond cargo test: `scripts/local-net.sh` + `scripts/cluster-test.sh` (no root); `docker/e2e.sh` needs `docker build --target test -t webjet:test .`; `docker/deploy-test.sh` tests the deployment image; `docker/tpm-test.sh` runs swtpm with `TPM2TOOLS_TCTI=swtpm:host=127.0.0.1,port=2321` and `WEBJET_TEST_TPM=1` — without a kernel resource manager every tpm2-tools step must `tpm2_flushcontext -t` or the TPM runs out of object slots (keystore does this). `docker/windows-test.sh` cross-builds with cargo-xwin and runs each test binary/test in its own Wine process (image scottyhardy/docker-wine:stable-9.0, linux/amd64; WINEPREFIX under $HOME, not /tmp). On Apple Silicon, Rosetta sometimes crashes Wine ("rosetta error") → counted EMU, not failure. Wintun/NRPT/service manager never ran on real Windows. Pitfall: a script created and launched in the same tool batch may run before `chmod +x` (permission denied) or with the old contents — run separately or via `sh script.sh`.
