`crates/webjet-app` is a GPUI (crates.io gpui 0.2.2) desktop app. It talks to the local webjetd control socket (like webjetctl) and signs ops with an account key via `webjet_tools::Account::unlock`/`sign` (moved from webjetctl into the webjet-tools lib). Permissions: admin = everything; normal account = read-only except rename/revoke of nodes it owns (`model::Session::may`); controllers enforce the same. `model.rs` + `client.rs` are GUI-free and unit-tested; `tests/live.rs` runs against `scripts/local-net.sh 2` (skips otherwise). Control channel `nodes` now includes `owner_id`. GPUI needs feature `runtime_shaders` on machines with only Command Line Tools (no `xcrun metal`). GPUI closures in `Application::run` must be 'static; app uses its own tokio runtime for IO and `cx.spawn` to update. Linux clippy in plain rust image must `--exclude webjet-app` (GPUI system deps). Screenshots of the window weren't possible here (no screen-capture/accessibility permission), so the GUI was only verified by launching and via the headless tests.

UI (crates/webjet-app/src/ui/) is one file per tab: dashboard.rs, connections.rs, nodes.rs, metrics.rs, accounts.rs; shared pieces + WebjetApp state in ui/mod.rs. GUI-free logic: model.rs (Snapshot incl. sessions/conntrack/topology/metrics as Result<_, String> so old agents still work; health(), Traffic, Summary), graph.rs (Graph::from_snapshot, deterministic Fruchterman–Reingold layout), openmetrics.rs (parser). Data comes from webjetd control commands `sessions` (circuit::summary), `conntrack` (dataplane::flows, each flow with the circuit its peer's e2e session sends on), `topology` (gossip::topology: LSA relay links, attachments, own hops), `metrics` ({"all":bool} on controllers). webjetctl has `local sessions|conntrack|topology`. Headless render test: `ui::tests::every_tab_renders` uses gpui `test-support` (dev-dependency) + TestAppContext/add_window_view/cx.draw, fed from crates/webjet-app/tests/fixtures/node-02.json (agent answers captured from `scripts/local-net.sh 4`, node-02 control socket; regenerate when the agent's JSON changes); screencapture doesn't work in this environment, rely on the headless test. GPUI gotcha: closures like `let opt = |r| ...` can't be generic; use nested `fn opt<T>(..)`.

Vendored gpui: Webjet uses patched copies of gpui 0.2.2 and gpui_media 0.2.2 in `vendor/gpui` and `vendor/gpui_media`, wired in through `[patch.crates-io]` in the workspace Cargo.toml (`exclude = ["vendor"]`). The patches let webjet-app cross-compile from Linux (builder:5) for macOS (commit b802713) and Windows (commit b851b22). Every changed place has a `Webjet:` comment (`grep -rn "Webjet:" vendor`); full list in `vendor/README.md`. Patches to redo after copying a new gpui (copy `build.rs`, `Cargo.toml`, `src/`, `resources/`, `LICENSE-APACHE` and `README.md` over the vendored copy, then `cargo update -p gpui -p gpui_media`): (1) gpui/build.rs `main`: pick steps by `env::var("CARGO_CFG_TARGET_OS")`, not `#[cfg(target_os)]` — "macos" → `macos::build()` (plus WGSL check if feature macos-blade), "windows" → `windows::build()`, else `check_wgsl_shaders()`; remove `#[cfg]` from `mod macos`, `mod windows` and `check_wgsl_shaders`. (2) gpui/build.rs `mod windows`: no `compile_shaders`/fxc.exe/`shaders_bytes.rs`, only `embed_resource()` — writes a copy of `resources/windows/gpui.rc` to OUT_DIR, replacing `"resources/windows/gpui.manifest.xml"` with the absolute path (forward slashes) and asserting it's present (cross-compiling: llvm-rc resolves the relative path against OUT_DIR, "file not found"). (3) gpui/src/platform/windows/directx_renderer.rs `mod shader_resources`: always compile at run time with `D3DCompile` (d3dcompiler_47.dll), sources `include_str!` of shaders.hlsl, color_text_raster.hlsl, alpha_correction.hlsl with `#include "alpha_correction.hlsl"` inlined by `replacen`; flags `D3DCOMPILE_OPTIMIZATION_LEVEL3` in release, `DEBUG|SKIP_OPTIMIZATION` in debug; profiles vs_4_1/ps_4_1, entry points `<module>_vertex`/`_fragment`; `RawShaderBytes` always holds an ID3DBlob; `ShaderModule::as_str` no longer debug-only. (4) gpui/src/platform/windows/destination_list.rs: replace ICU `u_strlen` (from `Win32::Globalization`) with `buffer.iter().position(|&c| c == 0)` — otherwise the exe imports icuuc.dll (only Windows 10 1903+; Wine lacks it) and fails to load. (5) gpui/Cargo.toml: bindgen, cbindgen, naga and embed-resource become unconditional `[build-dependencies]`; delete `[[example]]`/`[[test]]` targets (sources aren't copied). (6) gpui_media/build.rs: one `main` returning early unless `CARGO_CFG_TARGET_OS == "macos"`, instead of two `#[cfg]` mains; on Linux `xcrun --show-sdk-path` is answered by the scripts/macos-cargo.sh shim. Also in webjet-app (not vendored): main.rs has `#![cfg_attr(not(debug_assertions), windows_subsystem = "windows")]`.

Vendored-version check (commit 1d72b1c): `scripts/gpui-vendor-check.sh` compares the `[package] version` of vendor/gpui and vendor/gpui_media with the newest non-prerelease, non-yanked version in the crates.io sparse index (`https://index.crates.io/gp/ui/gpui`); exits 1 if crates.io is newer, 2 on errors. `.githooks/pre-commit` runs it with `--hook`: warning only, 5 s timeout, silent offline, caches the answer for a day in `$(git rev-parse --git-path gpui-vendor-check)`. Each clone enables the hook once with `git config core.hooksPath .githooks` (done in ~/Projects/webjet). Skip via `WEBJET_SKIP_GPUI_CHECK=1` or `git commit --no-verify`.

Verification recipe: run `.pi/tmp/app-all.sh`-style checks in builder:5 on root@10.4.0.9: `cargo xwin build --release -p webjet-app`, xwin/macos/freebsd clippy with -D warnings, `cargo test -p webjet-app`, `scripts/deny.sh`. Then run the exe under Wine (scottyhardy/docker-wine:stable-9.0 with `--entrypoint sh`, since its entrypoint drops root; Xvfb; `winetricks -q d3dcompiler_47 corefonts`; `GPUI_DISABLE_DIRECT_COMPOSITION=1`, because Wine lacks CreateSwapChainForComposition). Wine limits: its own d3dcompiler (vkd3d) can't parse shaders.hlsl (syntax error line 516), and its DirectWrite has no GetFontSet, so `select_font` panics at direct_write.rs:471 — the app has never shown a window under Wine. With native d3dcompiler_47 the DirectX renderer (all shaders) is created. As of b851b22 the app has not been run on real Windows. macOS cross-builds: `scripts/macos-cargo.sh <aarch64|x86_64>-apple-darwin build -p webjet-app` works in builder:5 (SDK 26.5, minos 11.0); release.sh ships `webjet-app-<tag>-<apple target>.tar.gz`; CI's macOS clippy includes webjet-app.
