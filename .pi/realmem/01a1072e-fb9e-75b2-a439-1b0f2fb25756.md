Two runtime changes lack a StateVersion gate, so all controllers must be upgraded before use; old controllers decode configs without new fields and halt on divergent leaf bytes.

1. `control` role (not fully backward-compatible):
- Pre-change controllers don't know `CreateEnrollment.control` / `UpdateNode.control` / `NodeRecord.control`; a leader setting the field makes leaf bytes old followers can't reproduce → divergence halt.
- Upgrade every controller before `--roles ...,control`.
- Old nodes accept only root-signed SigningKeyCerts (reject admin-signed, don't trust admin-only-certified heads, different offline_hash → gossip re-requests). Upgrade every node before `webjetctl controller certify`; until then use root-signed certs.
- Docs: architecture §6.5 (Upgrading); ops guide runbook 4 "You need".

2. `compression` field appended to TransportConfig and NodeConfig (new tree content; release 0.5.1 and older controllers lack it):
- On SetNetworkConfig or SetNodeConfig setting it, old controllers recompute different leaf bytes or treat compression-only NodeConfig as empty → divergence halt.
- Upgrade every controller network-wide/per node before the first `[transport.compression]` change.
- Nodes need no particular order: compressed messages go only to peers advertising `zstd`/`lz4`.
- Docs: ops guide 3.4 ("Releases without a StateVersion step"); architecture §9.8 "Upgrading".
