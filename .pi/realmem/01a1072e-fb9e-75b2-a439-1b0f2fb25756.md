The `control` role change is not fully backward-compatible at runtime, and there is no StateVersion gate for it:
- Controllers from before the change don't know `CreateEnrollment.control` / `UpdateNode.control` / `NodeRecord.control`. A leader that sets the field would produce leaf bytes old followers don't reproduce, so they halt on divergence. Upgrade every controller before using `--roles ...,control`.
- Old nodes accept only root-signed SigningKeyCerts. They reject admin-signed ones, don't trust heads from keys certified only by an admin, and their offline_hash differs from new nodes', so gossip keeps re-requesting offline items. Upgrade every node before `webjetctl controller certify`; until then use root-signed certs.
This is documented in architecture §6.5 (Upgrading) and in ops guide runbook 4's "You need".
