User decisions (2026-10): webjetup alone generates FreeBSD service files (no hand-installed copies in the repo); FreeBSD-native paths; the agent runs as root.
- `crates/webjetup/src/freebsd.rs`: `RcService::script()` generates rc.d scripts run by `/usr/sbin/daemon -P /var/run/<name>.pid -R <delay> -S -T <tag> -t <tag> <prog> <args>`. daemon passes SIGTERM on to the child at stop, restarts it after it exits, and sends its output to syslog. Two services: `webjetd` (`/usr/local/etc/rc.d/webjetd`, REQUIRE: NETWORKING syslogd, KEYWORD: shutdown, `webjetd_config` var, required_files) and `webjet_signer` (underscore: rc.subr names become shell variables; BEFORE: webjetd; tag `webjet-signer`). `install()` writes the script (0755) and runs `sysrc -f /etc/rc.conf.d/<name> <name>_enable=YES`. OPNsense starts every daemon enabled in /etc/rc.conf.d at boot (OPNsense docs "autorun"). stop = `service X onestop`; `state()` uses `service X onestatus`/`enabled`. The remote upgrade helper is a cron file `/usr/local/etc/cron.d/webjet-upgrade` that runs `webjetup apply-upgrade` every minute as root, logging to /var/log/webjet-upgrade.log. `webjetup nuke` also runs `ifconfig webjet0 destroy`.
- Paths: config `/usr/local/etc/webjet/webjetd.toml` (webjetd `default_config_path`), state `/var/db/webjet`, signer key `/var/db/webjet-signer/signing.key`, upgrade spool `/var/db/webjet-upgrade` (webjet-release `default_spool_dir`), runtime `/var/run/webjet`.
- `webjet_release::TARGETS` now has 6 entries, including `x86_64-unknown-freebsd`, and `target()` maps it. rollout's `pin_release` lists missing targets as a note. release.sh and CI don't build FreeBSD yet. `scripts/install.sh` accepts `FreeBSD` and uses `sha256 -q` as a fallback.
- Tests: rc.d scripts are checked with `sh -n`. Docs are in the README platform table, architecture §19.1 table (FreeBSD column + remote upgrade helper row), configuration.md (path, restart with `service webjetd restart`, OPNsense "memory file systems for /var" warning) and the ops guide signer line.
