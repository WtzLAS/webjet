- `crates/webjetd/src/tasks.rs`: `Supervisor` held as `Node::tasks`. Long-running loops start with `n.tasks.service(name, fut)` / `service_result` (ending at all — return, error, panic — is fatal: `run_until` logs it, calls `abort_all`, persists, cleans up, returns Err so systemd/launchd/Docker restart the agent) or `n.tasks.oneshot(name, fut)` (only a panic is fatal; used for start-dataplane, port-mapping, control-socket, metrics-endpoint). Services: controller, watch-control-role, gossip, e2e, paths, metrics, health, punch, connections, secrets, tls-listener, kcp-accept, anytls-listener, tun-writer, tun-reader, dataplane-refresh. Per-connection tasks stay `tokio::spawn`. `install_panic_hook` (called from `logging::init`, Once) logs panics via tracing. A new agent-lifetime loop must use `n.tasks.service`, not `tokio::spawn`, and must never return in normal operation.
- `crates/webjetd/src/control.rs`: `COMMANDS` table with `Access::{Read, Signed, Capability}`; `handle` rejects unlisted commands; unit tests parse `handle`'s match arms from the source (`include_str!`) and require they equal the table, and pin the non-Read set to submit_op, submit_offline, submit_signed, redeem_self, log. Limits: `MAX_REQUEST` 4 MiB per line (`read_request`), `MAX_CONNECTIONS` 64 (semaphore; extra get an error line). Ping `count` saturates to u16 instead of wrapping. Docs: docs/development.md "Agent tasks" and "The control channel".
