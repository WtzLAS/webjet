Every two-pane layout in crates/webjet-app/src/ui uses `WebjetApp::split(Split{id, axis: Row|Column, sized_first, default, min, rest_min}, first, second, cx)` from `ui/split.rs`. It returns a flex Div with a 12 px drag handle (`split::HANDLE`, also the gap between panes). The sized pane gets `flex_basis(size)` + shrink; the other gets `flex_1` + `min(rest_min)`. Build panes with `flex_1().min_h(0)`, never fixed `.w()` — do NOT add `.w(px(N)).flex_shrink_0()`. User sizes live in `WebjetApp.splits` (memory only, not persisted); double-click on a handle resets it. Dragging: `on_mouse_down` records the grab, `on_drag(Resize(id))` starts a GPUI drag rendering `Empty`; the container's `on_drag_move::<Resize>` calls `Splits::drag` with the container's extent. Handles get `debug_selector("split-<id>")`. Splits: Nodes ("nodes": graph column | node-side 420; "graph-circuits": Column, circuits 250 high; "circuits": list 440 | detail), connections, merkle-detail, merkle-ops, metrics, accounts, dash-traffic, dash-network.

Merkle tab (crates/webjet-app/src/ui/merkle.rs, part of a72d4f1): previously a fixed-height (`flex_shrink_0`) tree summary row with fixed-width Genesis (360) and signing-key (380) panels; in small windows (e.g. 1100×760) it pushed the leaves/details/log splits to 0 px, so separators couldn't be grabbed. Now `MERKLE_SUMMARY` (Column, summary sized first, default 240, min 100, rest_min 200) sits above `MERKLE_OPS`/`MERKLE_DETAIL`; inside the summary `MERKLE_HEAD` (head | genesis 360) and `MERKLE_KEYS` ((head|genesis) | certs 380). Summary panels use `summary_panel(id)` = scrolling panel. Test `ui::tests::merkle_separators_move` drags all five handles at 1435×852 … 1000×640 (drag direction shrinks the sized pane, since growing does nothing when the window already squeezes the other pane).

Nested scroll (GPUI 0.2.2, vendor/gpui `Interactivity::paint_scroll_listener`): every element with `overflow_y_scroll` under the pointer applies the wheel delta in the bubble phase and never calls `stop_propagation`, so a scrolling list inside a scrolling column scrolls both. Fix in webjet-app: `nested_scroll(id, &ScrollHandle)` in crates/webjet-app/src/ui/mod.rs is `scroll(id).track_scroll(handle).on_scroll_wheel(..)`; the handler calls `cx.stop_propagation()` while `handle.max_offset().height > 0`. Bubble listeners run innermost element first, so the list scrolls and the outer column never gets the event; a list that shows everything (max_offset 0) still lets the outer column scroll. Used for the Nodes tab's `node-list` (handle `WebjetApp.node_list_scroll`) inside `node-side`. Test `ui::tests::the_node_list_scrolls_alone` fails without the fix (checked). The old `side_scroll` helper is gone (replaced this fixed-width approach).

Shipped in v0.11.1, an annotated tag on bfa28a7 pushed with main to Forgejo, following the usual three-commit pattern: a72d4f1 = the fix; 3760fa8 = memories; bfa28a7 = version bump, install refs, and the ops-guide upgrade note "0.11.1 needs no order: only the desktop app changed." Before tagging, `cargo fmt --check`, workspace clippy (default and `--no-default-features`, `-D warnings`) and `cargo test --workspace` passed; Docker tests weren't run since only webjet-app changed. CI's release.yml builds and publishes all assets, including macOS (as for 0.11.0).

Layout regression test `ui::tests::nodes_tab_fits` drags handles by simulating mouse down, several moves, then up (the first move only starts GPUI's drag, past its 2 px threshold); it resizes the window and checks element bounds via `.debug_selector(|| "name".into())` + `cx.debug_bounds("name")` (needs gpui test-support; noop in release), measuring the last child to catch overflow.
