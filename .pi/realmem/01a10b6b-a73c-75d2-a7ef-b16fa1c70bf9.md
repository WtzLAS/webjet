Every two-pane layout in crates/webjet-app/src/ui uses `WebjetApp::split(Split{id, axis: Row|Column, sized_first, default, min, rest_min}, first, second, cx)` from `ui/split.rs`. It returns a flex Div with a 12 px drag handle (`split::HANDLE`, which is also the gap between the panes). The sized pane gets `flex_basis(size)` plus shrink, and the other pane gets `flex_1` + `min(rest_min)`. Panes should be built with `flex_1().min_h(0)`, never with a fixed `.w()` — do NOT add `.w(px(N)).flex_shrink_0()` to panes. User sizes live in `WebjetApp.splits` (in memory only, not persisted). A double-click on a handle resets it.

Dragging: on the handle, `on_mouse_down` records the grab and `on_drag(Resize(id))` starts a GPUI drag that renders `Empty`; the container's `on_drag_move::<Resize>` calls `Splits::drag` with the container's extent.

Splits: Nodes has "nodes" (graph column | node-side 420), "graph-circuits" (Column, circuits 250 high) and "circuits" (list 440 | detail). Other splits: connections, merkle-detail, merkle-ops, metrics, accounts, dash-traffic, dash-network.

The old `side_scroll` helper is gone (replaced this fixed-width approach). Handles get `debug_selector("split-<id>")`. Layout regression test `ui::tests::nodes_tab_fits` now drags handles by simulating mouse down, several moves, then up (the first move only starts GPUI's drag, past its 2 px threshold); it still resizes the window and checks element bounds via `.debug_selector(|| "name".into())` + `cx.debug_bounds("name")` (needs gpui test-support; noop in release), measuring the last child to catch overflow.
