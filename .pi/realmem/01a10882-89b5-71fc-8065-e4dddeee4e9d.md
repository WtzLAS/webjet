Only root can create or change an admin account: `put_account` in `crates/webjet-core/src/statemachine.rs` refuses with "admins can't create admins" and "only the root may change an admin account".

Adding an admin (docs/webjet-operations-guide.md section 1.2 — guide restructured from runbooks to chapters, old "runbook 13" = new 1.2; checked by docker/runbook-test.sh):
1. `webjetctl network account keygen --name carol --pub-out carol.pub`
2. Offline: `webjetctl root --dir … admin sign --name carol --key carol.pub --out carol.account`
3. On any enrolled node: `webjetctl network submit carol.account` — needs no account key; the agent routes it as SubmitRoot / RootAccountEntry.
The same steps with an existing account's `.pub` make that account an admin (keeps its ID and devices).

Account ID comes from the `.pub`, name from `--name`: same `.pub` under a new name renames the account; existing name with another key is refused ("account name X is taken"); re-submitting the same file is refused ("account version must increase" — versions are now_ms timestamps).

Key replacement (post-0.4.3, crates/webjet-tools): `webjetctl network account rekey <name> --key new.pub` (admin; normal accounts only — refuses admins) signs a new AccountRecord with the account's existing account_id and the new key; `webjetctl root admin sign --name X --key new.pub --replaces <old.pub | hex account id> --out X.account` does it for admins (root). Both rewrite the new `.pub` with the real account_id. `root admin revoke`/`root account revoke --key` accept a `.pub` or a hex account ID (`account_ref` in root.rs). Replacing an admin's key voids controller certs it signed (re-certify). Tested in docker/runbook-test.sh (section 1.4) and statemachine test `admin_revocation_and_account_rekey`.

Because `keygen` puts a random account_id in the `.pub`, `load_account` in webjetctl.rs is async and asks the agent (`accounts` call) which account holds this key; if the ID differs it uses the network's ID and rewrites `<keys>/<name>.pub` (prints a note).

Revoking an admin (fixed bug): in `crates/webjet-core/src/store.rs` `build_view`, an account tombstone replaces the account's leaf, so a revoked admin vanishes from `v.accounts`; the old issuer check `v.accounts.get(&issuer).map(..).unwrap_or(false)` made every normal account the admin created invalid even with `revoke_issued = false`, contradicting §13.4. Fix: if the issuer is absent but in `v.tombstoned_accounts`, its accounts stay valid unless the issuer is in `revoke_issuers`. Found by docker/runbook-test.sh section 1.3 (carol revoked, dave must stay); covered by statemachine test `admin_revocation_and_account_rekey`.

Pitfall (local-net, verified 2026-10-05 via scripts/local-net.sh): leftover local-net agents (e.g. /tmp/wj-acct) occupy port 17001; a new `scripts/local-net.sh` then fails with "controller did not start" (log: "bind 127.0.0.1:17001: Address already in use"). Check `pgrep -fl 'webjetd -c /tmp/'` and stop them with `scripts/local-net.sh stop <dir>`.
