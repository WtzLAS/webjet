Added after 0.4.3 (crates/webjet-tools): `webjetctl network account rekey <name> --key new.pub` (admin; normal accounts only — refuses admins) signs a new AccountRecord with the account's existing account_id and the new key; `webjetctl root admin sign --name X --key new.pub --replaces <old.pub | hex account id> --out X.account` does it for admins (root). Both rewrite the new `.pub` with the real account_id. `root admin revoke`/`root account revoke --key` accept a `.pub` or a hex account ID (`account_ref` in root.rs). Because `keygen` puts a random account_id in the `.pub`, `load_account` in webjetctl.rs is async and asks the agent (`accounts` call) which account holds this key; if the ID differs it uses the network's ID and rewrites `<keys>/<name>.pub` (prints a note). Replacing an admin's key voids controller certs it signed (re-certify). Tested in docker/runbook-test.sh (sections 1.4) and statemachine test `admin_revocation_and_account_rekey`.
