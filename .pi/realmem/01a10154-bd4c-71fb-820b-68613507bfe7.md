Integration tests beyond `cargo test` (table in docs/development.md):
- `scripts/local-net.sh [N]` (no root; whole network on 127.0.0.1), `scripts/cluster-test.sh` (leader failover), `scripts/soak-test.sh` (past the 120 s e2e re-key; catches timer-driven deadlocks), `cargo test -p webjet-app --test live` (needs local net; skips otherwise).
- `docker/e2e.sh` (real tun, DNS, policy, gateway; needs `docker build --target test -t webjet:test .`), `docker/deploy-test.sh` (deployment image check: genesis controller, enrolled node, ping, restart, SIGTERM, unenrolled error; per docs/docker.md).
- `docker/webjetup-test.sh` (install.sh/webjetup on a systemd container from fake release pages), `docker/runbook-test.sh` (ops runbooks 1, 2, 3, 4, 6, 8, 9 on systemd containers; `RELEASE=vX PORT=8443` uses a published release), `docker/release-test.sh vX` (published release in Debian 11, Ubuntu 20.04, Debian 12 × amd64/arm64). Systemd containers need `--privileged --cgroupns=host -v /sys/fs/cgroup:/sys/fs/cgroup:rw --tmpfs /run`; no `ps` — use `systemctl show -p MainPID` + `/proc`.
- `docker/tpm-test.sh`: swtpm with `TPM2TOOLS_TCTI=swtpm:host=127.0.0.1,port=2321` and `WEBJET_TEST_TPM=1`; without a kernel resource manager every tpm2-tools step must `tpm2_flushcontext -t` or the TPM runs out of object slots (the keystore does this).
- `docker/windows-test.sh`: cross-builds with cargo-xwin, each test in its own Wine process (scottyhardy/docker-wine:stable-9.0, linux/amd64, WINEPREFIX under $HOME). On Apple Silicon Rosetta sometimes crashes Wine ("rosetta error") → counted EMU, not failure. Wintun, NRPT and the Windows service manager have never run on real Windows.
Pitfalls: a script created and launched in the same tool batch may run before `chmod +x` or with old contents (run separately or via `sh script.sh`); BSD sed needs `;` before a closing `}`.

Deployment image = root `Dockerfile` (stages: build → base → `test` → `runtime`, default runtime). `docker build -t webjet .`; `--build-arg ANYTLS=0` skips BoringSSL; `--target test -t webjet:test` adds ping/dig/nc + scripts for `docker/e2e.sh`. Old `docker/Dockerfile` removed.

Remote test box `ssh root@10.4.0.9` (amd64, Docker 29) for running docker tests: local Mac Docker builds of the test image are slow/stuck. Sync sources: `git ls-files -co --exclude-standard | rsync -az --files-from=- ./ root@10.4.0.9:/root/webjet-realip/` (plain rsync of the repo drags 50+ GB of target*/fuzz dirs). The Dockerfile build stage fails there with RUST_IMAGE=webjet-builder (Debian 11 apt conflict libc6-i386) and rust:1-bookworm pulls are slow — instead compile in the builder image: `docker run --rm -v $PWD:/src -v webjet-realip-target:/src/target -v webjet-realip-registry:/usr/local/cargo/registry -w /src forgejo.wolf109909.top/webj8-internal/webjet-builder:5 sh -c "cargo build --release --locked --no-default-features -p webjetd -p webjet-tools && mkdir -p out && cp target/release/webjetd target/release/webjetctl out/"` (~4.5 min cold), then `docker build -f /root/Dockerfile.prebuilt --target test -t webjet:test .` (Dockerfile.prebuilt = `ARG DEBIAN_IMAGE=debian:12-slim` + `FROM debian:12-slim AS build` + `COPY out/ /out/` + the Dockerfile from "runtime contents" on). 172.30.0.0/16 is taken on the box (clash_default), so test nets must use another prefix: docker/node.sh and docker/realip-test.sh honor `WAN_PREFIX` (e.g. `WAN_PREFIX=10.88 sh docker/realip-test.sh`); docker/e2e.sh still hardcodes 172.30. .dockerignore now excludes `target-*` and `dist` (target-linux 13 GB made local builds hang on context transfer).

`docker/entrypoint.sh` (via tini) generates `/run/webjet/webjetd.toml` from `WEBJET_*` env vars (header marks it generated, regenerated each start) unless `/etc/webjet/webjetd.toml` is mounted. First start with no `$DATA/node.json`: runs `webjetctl local init --genesis $WEBJET_GENESIS` or `webjetctl local enroll <string>` (0.4.0). `webjetd` reads `WEBJET_CONFIG` env (path must exist). Healthcheck = `docker/healthcheck.sh` (`webjetctl --json local status`).

Controller has no `WEBJET_CONTROLLER=true` switch: roles unified (`--roles data,relay,control`); entrypoint writes `[controller] enabled = false` only when `WEBJET_CONTROLLER` is a false value, else nothing — controller starts when node has control role or on genesis (`WEBJET_GENESIS`). `-e WEBJET_CONTROLLER=true` removed from docs/docker.md, docker/compose.example.yaml, docker/deploy-test.sh, docker/webjetup-test.sh; in docker/node.sh (e2e) the second arg is now the gateway prefix.

`WEBJET_RELAY_CAPACITY_MBPS`/`WEBJET_RATE_CEILING_MBPS` removed (limits are node config in the tree); entrypoint dies with hint to use `webjetctl local config --node <name> set limits.value.relay_capacity_mbps N`.

Network config applied as TOML by `docker/e2e.sh`, `docker/deploy-test.sh`, `webjetup-test.sh` via `webjetctl network config apply` (or `network config set policy.default allow` / `set seeds '[…]'`). Docs: docs/docker.md; Compose: docker/compose.example.yaml.
