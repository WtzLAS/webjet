Deployment image is the root `Dockerfile` (stages: build → base → `test` → `runtime`, default runtime). `docker build -t webjet .`; `--build-arg ANYTLS=0` skips BoringSSL; `--target test -t webjet:test` adds ping/dig/nc + scripts for `docker/e2e.sh`. Old `docker/Dockerfile` was removed.

`docker/entrypoint.sh` (via tini) generates `/run/webjet/webjetd.toml` from `WEBJET_*` env vars (header line marks it generated, regenerated each start) unless `/etc/webjet/webjetd.toml` is mounted. On first start with no `$DATA/node.json` it runs `webjetctl local init --genesis $WEBJET_GENESIS` or `webjetctl local enroll <string>` (0.4.0). `webjetd` reads `WEBJET_CONFIG` env (a given path must exist). Healthcheck = `docker/healthcheck.sh`, which runs `webjetctl --json local status`.

`WEBJET_RELAY_CAPACITY_MBPS`/`WEBJET_RATE_CEILING_MBPS` env vars were removed (limits are node configuration in the tree now); the entrypoint dies with a hint to use `webjetctl local config --node <name> set limits.value.relay_capacity_mbps N`.

Network configuration is applied as TOML by `docker/e2e.sh`, `docker/deploy-test.sh` and `webjetup-test.sh` via `webjetctl network config apply` (or `network config set policy.default allow` / `set seeds '[…]'`). Docs: `docs/docker.md`; Compose: `docker/compose.example.yaml`. `docker/deploy-test.sh` is the end-to-end check for the deployment image (genesis controller, enrolled node, ping, restart, SIGTERM, unenrolled error).
