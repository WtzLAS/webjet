Deployment image is the root `Dockerfile` (stages: build → base → `test` → `runtime`, default runtime). `docker build -t webjet .`; `--build-arg ANYTLS=0` skips BoringSSL; `--target test -t webjet:test` adds ping/dig/nc + scripts for `docker/e2e.sh`. Old `docker/Dockerfile` was removed.

`docker/entrypoint.sh` (via tini) generates `/run/webjet/webjetd.toml` from `WEBJET_*` env vars (header line marks it generated, regenerated each start) unless `/etc/webjet/webjetd.toml` is mounted. On `webjetd run` with no `$DATA/node.json` it runs `webjetd init --genesis $WEBJET_GENESIS` or `webjetd enroll $WEBJET_ENROLL`/`WEBJET_ENROLL_FILE`. `webjetd` reads `WEBJET_CONFIG` env (a given path must exist). Healthcheck = `webjetctl --json status` (role file /run/webjet-role). Docs: `docs/docker.md`; Compose: `docker/compose.example.yaml`. `docker/deploy-test.sh` is the end-to-end check for the deployment image (genesis controller, enrolled node, ping, restart, SIGTERM, unenrolled error).
