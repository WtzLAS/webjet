- `webjet_core::frames::SessionKey` (e2e frames, every data packet) uses `aws_lc_rs::aead::LessSafeKey` CHACHA20_POLY1305 (workspace dep `aws-lc-rs = { default-features=false, features=["aws-lc-sys","prebuilt-nasm"] }`, same lib as rustls provider) instead of RustCrypto chacha20poly1305 (~2.5x faster on arm64). RustCrypto stays a dev-dep of webjet-core for test `frames_match_the_rustcrypto_implementation` (wire compatibility with older nodes). `webjet_net::gate` still uses RustCrypto XChaCha20-Poly1305 (aws-lc-rs has no XChaCha).
- Benchmark: `cargo test --release -p webjetd --lib e2e::tests::data_path_cost -- --ignored --nocapture` (`WEBJET_BENCH_ROUNDS`, default 200000). M-series: 2.8/2.5 µs send/recv per 1200 B packet before, 1.5/1.3 µs after; AEAD dominates the rest. Profile with `sample <pid>` on macOS (binary from `cargo test --release --no-run`).
- `[profile.dev.package.kcp] overflow-checks = false` in Cargo.toml (and dev+release in fuzz/Cargo.toml): kcp 0.6 `timediff`/`rcv_nxt + rcv_wnd` wrap by design with plain +/-; the fuzz smoke test found debug-build panics (regressions fuzz/regressions/kcp_session/kcp-wrapping-{sn,ts}). Release builds were unaffected. The fuzz smoke test uses a random seed per run, so failures can be intermittent—rerun with the printed WEBJET_FUZZ_SEED.
