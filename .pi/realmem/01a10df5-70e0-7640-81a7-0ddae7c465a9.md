- `crates/webjet-proto/src/serde_impls.rs`: Key32/Sig64/Id16 serialize as hex, IpAddress/SockAddr/Cidr as `ip`, `ip:port`, `ip/prefix` (unset = ""); deserialization also accepts the old `{"b0":…}`/`{"family":…}` struct form. `regen.sh` perl-strips the derived serde impls of those structs after planus runs — keep that step.
- webjetctl (user chose "keep human output, fix JSON"): `report(cli, text, json)` prints a sentence or, with `--json`, an object (`entry` = log index, `node_id` hex, enrollment strings under `enroll`). `call()` passes replies through `legacy_ids` so 0.6 agents' `{b0..b3}` ids become hex. `controller list` gets `node_names` {id: name} via `with_node_names`.
- `webjet_tools::find_id(items, query, suffix, what, skip)`: name, `name.<dns suffix>`, full hex id (case-insensitive), unique hex prefix ≥4 digits, or base64 key. Used by `node_id()`/`account_id()` in webjetctl so every node/account argument accepts ids. `local ping` resolves names/ids to the overlay IP client-side (works with old agents). Agent `status` now has `dns_suffix`, `nat`, `port_mapping`.
- Loopback fix: `Dataplane::outbound` reflects packets to the node's own overlay IPs back into the tun (`loopback()`); macOS utun has no lo route for its own address. Own control-channel pings to self are answered there.
- webjet-app Nodes detail shows NAT type, advertised endpoints and port mapping from `topology` nodes' `nat`/`endpoints`/`port_mapping` (from EndpointRecords; own values live).
