Every role is assigned via `--roles` (`webjetctl network node enroll|update --roles data,relay,control`); admins, not only root, may grant CONTROL (0.4.0 command paths; earlier design had CONTROL only from a root-signed cert plus `[controller] enabled = true`).

Wire format (append-only):
- `NodeRecord.control: bool = null`. Absent = pre-control-role record; root-signed cert alone still grants CONTROL for those.
- `CreateEnrollment.control: bool`, `UpdateNode.control: bool = null` (set or clear).
- `SigningKeyCert.issuer: [ubyte]` = signing admin's root-signed AccountRecord; absent when root signs.
- RPC `GetCertRequest`/`CertRequestReply`.
- `wp::Role` still only Data/Relay; `webjet_core::types::Roles{data,relay,control}` + `parse_roles` map `--roles` onto wire fields.

Rules:
- `View::controllers`: valid node, valid cert, `rec.control == Some(true)`, or `None` with root cert.
- `View::valid_certs` (key ids) drives head verification; depends only on certs/accounts, never node records.
- Revoking an admin or rotating its key voids all certs it signed (no "signed before revocation" check; certs unordered in log).
- Store keys certs by hash of bytes; root cert replaces admin certs for same key; one cert per (key, admin); key certifiable for one node only.
- `offline_hash`: root certs by key id, admin certs by cert hash.
- State machine: AddLearner needs `control == Some(true)`; cannot remove control from Raft member; bootstrap fixed-id enrollment requires control.

Agent: `agent.rs` `maybe_start_controller`/`watch_control_role` start controller role on bootstrap node or when tree grants CONTROL (HeadChanged, no restart). `[controller] enabled` plain bool (default true; false opts out even with CONTROL). Control socket `cert_request` takes optional `node` (hex), fetches over overlay. `nodes`/`status` show `control` (in effect) + `control_role`; `node list` prints `control(uncertified)` for granted role without valid cert.

CLI: `webjetctl network controller certify <name> [--request f]` (admin key; fetches account record via `accounts` control call, field `record`) and submits; `webjetctl network controller cert-request --out f [--node n]` + `webjetctl root controller sign` = root alternative. Shared helper `webjet_tools::certify`.

Runtime-compat rollouts (no StateVersion gate — upgrade ALL controllers before use; old controllers decode configs without new fields and halt on divergent leaf bytes):
1. `control` role (not fully backward-compat): pre-change controllers don't know `CreateEnrollment.control`/`UpdateNode.control`/`NodeRecord.control`; leader setting the field → leaf bytes old followers can't reproduce → divergence halt. Upgrade every controller before `--roles ...,control`. Old nodes accept only root-signed SigningKeyCerts (reject admin-signed, don't trust admin-only-certified heads, different offline_hash → gossip re-requests): upgrade every node before `webjetctl controller certify`; until then use root-signed certs. Docs: architecture §6.5 (Upgrading); ops runbook 4 "You need".
2. `compression` field appended to TransportConfig and NodeConfig (new tree content; release 0.5.1 and older controllers lack it): on SetNetworkConfig/SetNodeConfig setting it, old controllers recompute different leaf bytes or treat compression-only NodeConfig as empty → divergence halt. Upgrade every controller network-wide/per node before first `[transport.compression]` change. Nodes need no particular order: compressed messages go only to peers advertising `zstd`/`lz4`. Docs: ops guide 3.4 ("Releases without a StateVersion step"); architecture §9.8 "Upgrading".

Docker: `WEBJET_CONTROLLER` only writes `enabled = false` when set false.
