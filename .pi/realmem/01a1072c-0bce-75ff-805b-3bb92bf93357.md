Every role is assigned via `--roles` (`webjetctl network node enroll|update --roles data,relay,control`), and admins, not only the root, may grant CONTROL (0.4.0 command paths; earlier design had CONTROL only from a root-signed cert plus `[controller] enabled = true`).

Wire format (append-only):
- `NodeRecord.control: bool = null`. Absent means a record from before control was a role; for those, a root-signed cert alone still grants CONTROL.
- `CreateEnrollment.control: bool`, `UpdateNode.control: bool = null` (set or clear).
- `SigningKeyCert.issuer: [ubyte]` = the signing admin's root-signed AccountRecord; absent when the root signs.
- RPC `GetCertRequest` / `CertRequestReply`.
- `wp::Role` still has only Data/Relay. `webjet_core::types::Roles{data,relay,control}` and `parse_roles` map the `--roles` string onto the wire fields.

Rules:
- `View::controllers` lists a node only if it is valid, has a valid cert, and `rec.control` is `Some(true)`, or is `None` with a root cert.
- `View::valid_certs` (key ids) is what head verification uses. It depends only on certs and accounts, never on node records.
- Revoking an admin, or giving an admin a new key, voids every cert that admin signed. Certs aren't ordered in the log, so there's no "signed before the revocation" check.
- The store keeps certs keyed by the hash of their bytes. A root cert replaces the admin certs for the same key. One cert per (key, admin). A key can be certified for one node only.
- `offline_hash` hashes root certs by key id, as before, and admin certs by cert hash.
- The state machine refuses AddLearner without `control == Some(true)`, refuses removing control from a Raft member, and requires control for the bootstrap fixed-id enrollment.

Agent: `agent.rs` `maybe_start_controller` / `watch_control_role` start the controller role on the bootstrap node or as soon as the tree grants CONTROL (on HeadChanged, no restart). `[controller] enabled` in webjetd.toml is a plain bool again (default true; `false` opts out of running the controller role even with CONTROL) — the 0.3-era `Option<bool>` with a warning for `true` is gone. Control socket `cert_request` takes an optional `node` (hex) and fetches that node's request over the overlay. `nodes`/`status` show `control` (in effect) and `control_role`. `node list` prints `control(uncertified)` for a granted role without a valid cert.

CLI: `webjetctl network controller certify <name> [--request f]` signs with the admin key (it fetches the account's record from the `accounts` control call, field `record`) and submits. `webjetctl network controller cert-request --out f [--node n]` plus `webjetctl root controller sign` is the root alternative. Shared helper: `webjet_tools::certify`.

Docker: `WEBJET_CONTROLLER` only writes `enabled = false` when set to false.
