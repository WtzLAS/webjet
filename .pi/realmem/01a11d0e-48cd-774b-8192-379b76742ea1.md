The Forgejo runner on root@10.4.0.9 (208 cores) starts job containers with a 1024 open-file limit, and ignores `container: options: --ulimit nofile=…` in the workflow (tried in 45963b9; lint still failed in run 83). With webjet-app in the workspace, cargo's default of one job per core hit "Too many open files (os error 24)". The fix (commit e44c35f) is the top-level `env: CARGO_BUILD_JOBS: "64"` in ci.yml, release.yml and fuzz.yml. scripts/freebsd-cargo.sh also raises `ulimit -n` up to the hard limit (max 65536). Raising the limit in the runner config (/root/docker/forgejo-runner/data/runner-config.yml, `container.options`) would affect every repo, so it was left alone. The runner's proxy sometimes sends an empty reply (curl 52), so downloads use `--retry 5 --retry-all-errors` (scripts/deny.sh, freebsd-sysroot.sh, the builder Dockerfile).
