`fuzz/` is its own Cargo workspace (not in `cargo test --workspace`). `fuzz/src/lib.rs` has one `pub fn` per target (proto, frames, packet, decompress, gate, kcp_session, hop_record, dns) plus `TARGETS`; `fuzz/fuzz_targets/*.rs` are thin libFuzzer wrappers (feature `libfuzzer`, default). Seeds in `fuzz/src/seeds.rs` (`cargo run --manifest-path fuzz/Cargo.toml --no-default-features --example seeds` writes fuzz/corpus/).
- Stable smoke test (CI ci.yml `test` job): `cargo test --release --manifest-path fuzz/Cargo.toml --no-default-features` — seeds + random mutations (`WEBJET_FUZZ_ITERS`, `WEBJET_FUZZ_SEED`) and replays fuzz/{corpus,artifacts,regressions}/<target>/.
- Real fuzzing: `scripts/fuzz.sh [secs] [targets]` (needs `rustup toolchain install nightly` + `cargo install cargo-fuzz`); logs in fuzz/target/fuzz-<t>.log; `.forgejo/workflows/fuzz.yml` runs it nightly.
- Daemon-internal hooks: `webjet_net::kcp::fuzzing` (session_input, scan) and `webjetd::dns::fuzzing::query_and_answer` (#[doc(hidden)] pub mods).
- Commit crash inputs to `fuzz/regressions/<target>/`. First finding (fixed): `fec::Decoder::push` panicked on a 1-byte parity shard (recovered slot shorter than its 2-byte length prefix); now parity shards are validated (k ≤ GROUP_DATA, 1 ≤ m ≤ GROUP_DATA, idx in k..k+m, consistent k/m per group, width ≥ 2 and ≥ every data shard + 2).
- Pitfall: don't `git stash` sources while a fuzz/cargo build runs in the background — it may compile the stashed version.
