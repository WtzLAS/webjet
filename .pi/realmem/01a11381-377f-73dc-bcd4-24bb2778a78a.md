- crates/webjetd/src/rpc.rs: pending calls are `HashMap<id, (peer, Sender)>` with random u64 ids (never 0, which one-way messages carry); `deliver(from, id, body)` ignores responses from any node but the called one; `PendingGuard` removes the entry on drop (cancelled calls don't leak).
- crates/webjetd/src/state.rs `write_private`: each write goes through `.{name}.{random}.tmp` (create_new, 0600, fsync, rename, removed on error), then fsyncs the parent dir on Unix. Concurrent saves of the same file (store.json) can't mix contents. It still calls `restrict_dir(parent)` (known issue: harmful for user-chosen paths in webjetctl/root — Phase 3 item).
- crates/webjet-core/src/store.rs `Store::install`: checks each update against the tree *before* the sync, rejects a leaf listed twice, refuses removing or replacing Node/Account tombstones; resending an unchanged leaf is fine. Unit tests in store.rs `tests` use `testutil::Cluster` + a forged head signed by `c.head_key`.
