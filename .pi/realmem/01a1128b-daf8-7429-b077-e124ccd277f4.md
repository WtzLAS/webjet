Changed after 0.8.0. Under load, e2e probes and keepalives queued behind the circuit's own data (HopQueue → KCP duplex → KCP send queue/pacer, or the TCP send buffer). Their RTT/loss shot up and sessions switched to idle circuits.

Fix:
- **`crates/webjet-net/src/meter.rs`**: `Meter::{Kcp, Tcp}` and `Sample { rtt_ms: Option<(mean, min)>, loss, packets }`.
  - `MeteredTcp` wraps the TcpStream for TCP+TLS and AnyTLS, dial and accept. Its `TcpMeter` reads `TCP_INFO` (Linux), `TCP_CONNECTION_INFO` (macOS) or `SIO_TCP_INFO` (Windows).
  - macOS uses its own `TcpConnectionInfo` struct (112 bytes): libc's struct has the TFO bitfield as 15 separate u32s, so every counter after it was read at the wrong offset (sent=0).
- **`kcp.rs`**: new datagram kind `K_RAW_ACK = 5` (`held_us[4] || KCP ACK segments`). It is sent at once, outside FEC and the pacer, and only to peers whose STATS carry flag byte 1 (STATS is now 14 bytes; older peers send 13). The receiver subtracts `held`.
  - `RawRtt` measures from a segment leaving the socket (after the pacer) to its ACK; Karn's rule applies. The datagram arrival time is passed with each datagram (`Arrived = (Instant, Vec<u8>)`).
  - Loss is the FEC shard-group loss in both directions. BBR's min_rtt uses the raw RTT.
  - DUPLEX is 512 KB → 64 KB. User data is taken only while `paced.len() < bbr.window()`.
- **`LinkStats` (`routing.rs`)**: `on_raw(rtt, loss, packets, now_us, now_ms)`. After the first raw RTT, `raw = true`, and keepalive acks/losses no longer move srtt or loss. `outcomes` are now (lost, total) pairs. `LinkHistory::observe_raw`.
- **`node.rs` keepalive** reads `hop.meter.take()` every 2 s and feeds `on_raw`. The writer's CoDel `tune` uses the KCP bw estimate as its rate.
- **Circuit cost (`paths.rs` `path_cost`, `circuit.rs` `LocalCircuit::cost`)**: live first hop + `Graph::link` (relay links / attachments) along `relays_from_me()`. There is no load penalty; a full relay ×4.
  - Probe cost is used only while links are unknown. Cost is infinite after a probe goes unanswered for 3 s with nothing received.
  - Probes are skipped when `busy()`: at least 3 session frames each way per 1 s interval (`Live.tx/rx` counters in e2e send/on_frame). Idle circuits are still probed every second.
  - `sessions` JSON has `cost` per circuit.
- **Test**: `docker/load-test.sh` (subnets 172.33.x; each data node enrolls via the controller IP on its own network; the test image needs `-e WEBJET_CONFIG=/etc/webjet/webjetd.toml`). Result: 0 switches during 40 s of bulk transfer, 0 probes on the loaded circuit, 37 on the idle one.
