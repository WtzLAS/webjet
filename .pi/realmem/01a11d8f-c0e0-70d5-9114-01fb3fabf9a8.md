User decision (after v0.11.6): webjet-app is packaged inside the main `webjet-<tag>-<target>` archive next to webjetd/webjetctl (Windows zip too); the separate `webjet-app-<tag>-<target>` archive is no longer published. webjetup installs webjet-app into the programs dir on every platform (Linux, FreeBSD, macOS, Windows); it is optional so older releases without it still install.

Context from earlier release (v0.11.0, annotated tag on 0ec9f20, pushed with main; notes covered broadcast/multicast + capture §9.5.1/9.5.2, FreeBSD 14 / OPNsense 24.7+ x86_64, the desktop app, webjetup SOCKS proxies): release.yml alone published the release with 38 assets (main + app archives for 6 targets, webjetup, install.sh, sha256 files); the macOS arm64 app archive passed sha256 and `codesign -v` and started on the Mac; the Windows app had not been run on real Windows; `docker/webjetup-test.sh` was not run before tagging; `docker/release-test.sh v0.11.0` had not been run yet. Ops guide note "Releases without a StateVersion step": nodes need no order; upgrade every controller before the first `multicast_*` limit or `[multicast]` capture setting.
