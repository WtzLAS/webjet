Why: a node whose clock is more than 60 s off (`SKEW_PSK_GATE`) is dropped silently at every PSK gate, including enrollment. Enrollment then just fails with an opaque TLS error from every controller. This was seen on a Windows machine in 2026-10. Added after v0.12.0:
- `crates/webjet-core/src/sntp.rs` is a std-only SNTP client. `offset(servers, TIMEOUT=3s)` queries all servers in parallel threads and returns `Offset{server, ahead_ms (median, positive = local clock ahead), answers}`. Also `describe()`, `fix_hint()` (per-platform fix command), built-in `SERVERS` (time.cloudflare.com, ntp.aliyun.com, time.windows.com, pool.ntp.org). The live test is ignored: `cargo test -p webjet-core --lib sntp -- --ignored --nocapture`.
- webjetd.toml `[clock] servers` (`ClockCfg`): when left out, the built-in list is used; `[]` turns the check off. Webjet never sets the clock itself (except webjetup on Windows).
- `agent::enroll`: after every controller failed, it calls `clock_problem(cfg)`. If the clock is more than 60 s off it bails with the offset and the fix hint; otherwise the error adds a hint about an expired/used string or reachability. Helpers: `agent::clock_offset`, `clock_message`.
- `health::check_alone` (in `health::run`): when the node has had no hop for `ALONE_AFTER` 120 s while the tree has other valid relays/controllers, it asks the time servers, then again every `ALONE_RECHECK` 600 s. More than 60 s off raises the `clock_skew` alarm (critical) and logs an error. The timing logic is in the testable struct `Alone::due`.
- webjetup `crates/webjetup/src/clock.rs` `check()` runs from `do_enroll` before enrolling ("==> Checking the clock"). It reads `[clock] servers` from the config. On Windows it sets `sc config W32Time start= auto` plus `sc start W32Time`. If the clock is more than 10 s off, it runs `w32tm /resync /force`, and if that fails, `w32tm /config /manualpeerlist:... /syncfromflags:manual /update` and resyncs again. Other platforms only print the fix hint. webjetup now depends on webjet-core.
- Docs: architecture §18.6 "Unable to connect" bullet; configuration.md `### [clock]` section after `[upgrade]`.
