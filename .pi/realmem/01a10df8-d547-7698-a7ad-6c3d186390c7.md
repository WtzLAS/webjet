v0.7.0 is an annotated tag on commit d081161, pushed to origin main on Forgejo (2026-10). Contents since v0.6.1: automatic controller membership (547c220), relay capacity/route discovery fixes (94d34d2), ICE-style hole punching (§11.7 rework) with checks / peer-reflexive / port prediction / UPnP-NAT-PMP-PCP, tunnel-interface exclusion and webjetd.toml `[nat]`, loopback to own overlay IP, webjetctl hex ids + consistent --json + id/prefix lookup, NAT type in webjet-app.

Hole-punching rework details:
- `crates/webjetd/src/nat.rs`: tunnel-interface detection (POINTOPOINT flag + name prefixes wg/tun/utun/tap/tailscale/zt/ppp/ipsec/nordlynx…; overlay `webjet*` always excluded), `candidate_ips` (public first, max 8; replaces old `platform::local_ips` which sorted+truncated to 4 and dropped public IPs), `via_tunnel(dst)` (egress via connected UDP socket; full-tunnel VPN carrying the default route is allowed), `dialable()`, router port mapping (crab_nat PCP/NAT-PMP then igd-next UPnP; only if external IP is global; released at shutdown). webjetd.toml `[nat]`: skip_tunnels, exclude_interfaces, allow_interfaces (globs), exclude_cidrs, port_mapping.
- `crates/webjet-net/src/kcp.rs`: K_PUNCH datagrams carry type (1 PING / 2 PONG) + 16-byte token (= punch nonce); PING answered with PONG to source (rate-limited 2000/s); events to `UdpEndpoint::punch_events`. Old padding-only PUNCH ignored.
- `crates/webjetd/src/punch.rs`: OFFER/OFFER/GO, checks to all candidates for 6 s (50 ms then 200 ms), peer-reflexive candidates learned from PINGs, port prediction (+96/−8) when peer symmetric and we aren't, first PONG nominates; lower id dials, higher id after 1.5 s; blind parallel dial fallback; either side starts (higher id 5 s later); retry 15 s doubling to 5 min, immediately on RecordsChanged/HopDown. `punch::status` appears under `punch` in `local sessions`.
- `transport::nat_type` counts only observations from RELAY hops (a punched data-node hop's observed port can differ and made a cone NAT look symmetric).
- Test: `docker/nat-test.sh` (MODE=symmetric too) — two iptables NAT routers, public node without NAT, fake `wg0` VPN subnet that must not be used, loopback pings. Docker pitfalls: `--internal` networks drop forwarded traffic leaving the subnet; .1 is the Docker gateway (routers use .2); NAT routers must DROP unsolicited WAN traffic in INPUT too, else a conntrack entry from the peer's early PING steals the port and MASQUERADE picks a new one.

CLI/JSON conventions:
- `crates/webjet-proto/src/serde_impls.rs`: Key32/Sig64/Id16 serialize as hex, IpAddress/SockAddr/Cidr as `ip`, `ip:port`, `ip/prefix` (unset = ""); deserialization also accepts the old `{"b0":…}`/`{"family":…}` struct form. `regen.sh` perl-strips the derived serde impls of those structs after planus runs — keep that step.
- webjetctl (user chose "keep human output, fix JSON"): `report(cli, text, json)` prints a sentence or, with `--json`, an object (`entry` = log index, `node_id` hex, enrollment strings under `enroll`). `call()` passes replies through `legacy_ids` so 0.6 agents' `{b0..b3}` ids become hex. `controller list` gets `node_names` {id: name} via `with_node_names`.
- `webjet_tools::find_id(items, query, suffix, what, skip)`: name, `name.<dns suffix>`, full hex id (case-insensitive), unique hex prefix ≥4 digits, or base64 key. Used by `node_id()`/`account_id()` in webjetctl so every node/account argument accepts ids. `local ping` resolves names/ids to the overlay IP client-side (works with old agents). Agent `status` now has `dns_suffix`, `nat`, `port_mapping`.
- Loopback fix: `Dataplane::outbound` reflects packets to the node's own overlay IPs back into the tun (`loopback()`); macOS utun has no lo route for its own address. Own control-channel pings to self are answered there.
- webjet-app Nodes detail shows NAT type, advertised endpoints and port mapping from `topology` nodes' `nat`/`endpoints`/`port_mapping` (from EndpointRecords; own values live).

Install references in README.md, scripts/install.sh and the ops guide name v0.7.0. Release notes tell users to upgrade all controllers first (auto membership). The macOS assets still have to be uploaded by hand after the CI release job (see the release memory).
