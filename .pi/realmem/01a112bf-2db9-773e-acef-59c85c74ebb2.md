Since 0.9.0, the `kcp` crate is no longer a dependency. It is kept only as a webjet-net dev-dependency for the `interoperates_with_the_kcp_crate` test, which guards rolling upgrades from ≤0.8 nodes.

**`crates/webjet-net/src/kcp/proto.rs` (`proto::Kcp`):**
- Stream mode only, with the same wire format as upstream.
- `send(data, now_us)`
- `flush(now_us, budget_bytes, &mut Output{control, data})`: retransmits first, then new data within the pacer budget and window. ACKs and window probes go in `control`.
- `input(pkt, arrived_us, held)` (ACK parsed before `una`, so its RTT sample isn't lost)
- `recv()`, `queued_bytes()`, `backlog_age()`, `take_rtt_samples()` (raw, Karn, minus held), `take_delivered()`, `take_retransmits()`, `is_dead()`
- Use wrapping arithmetic and `diff()`, never plain +/-.

**`kcp/mod.rs` `run_session`:**
- No OutQueue, scan_output, RawRtt or `paced` queue any more.
- `Pacer` has `budget()`/`spend()` and can be overdrawn.
- User data is taken while `kcp.queued_bytes() < queue_limit(rate)`, about 5 ms of rate, at least 4 MTU. DUPLEX is 16 kB.
- `KcpStats.backlog_us` → `HopQueue.below` (webjet-core queue.rs): added to every frame's sojourn, so CoDel marks or drops when the backlog sits inside KCP. Set in the node.rs writer before each pop.
- `Delivery::on_tick(delivered_bytes, idle, now, min_interval, app_limited)`.

**Result** (docker load test, 20 Mbit/s with 15 ms access links): overlay ping under bulk load fell from 146 to 77 ms (idle 31). With `tcp_ecn=1` inside the containers, ECN marks show up at the destination (`webjet_route_ecn_marked_total`).

Why `ecn_marked` is normally 0 in the field: inner TCP rarely negotiates ECN (Linux `tcp_ecn=2` default), so CoDel drops instead (`aqm_dropped`).

ECN experiment script: /tmp/ecn-test.sh, not committed. It is a copy of docker/load-test.sh with `--sysctl net.ipv4.tcp_ecn=1` plus a metrics dump.

**kcp crate overflow-checks off:** `[profile.dev.package.kcp] overflow-checks = false` in Cargo.toml (and dev+release in fuzz/Cargo.toml): kcp 0.6 `timediff`/`rcv_nxt + rcv_wnd` wrap by design with plain +/-; the fuzz smoke test found debug-build panics (regressions fuzz/regressions/kcp_session/kcp-wrapping-{sn,ts}). Release builds were unaffected. The fuzz smoke test uses a random seed per run, so failures can be intermittent—rerun with the printed WEBJET_FUZZ_SEED.
