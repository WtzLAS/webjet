Since commit c8737c8, `crates/webjet-core/src/store.rs` works like this.

**Adding offline items**
- `add_cert`, `add_key_tombstone`, `add_offline_tombstone` and `add_offline_item` each call an `insert_*` twin that does not rebuild. They then call `rebuild_if_added`, which rebuilds only on `Ok(true)`.
- `Store::add_offline_items(items) -> Vec<Result<bool>>` takes any `IntoIterator` of `AsRef<[u8]>`. It inserts every item and then rebuilds once, only if at least one item was added. The result is identical to adding the items one by one, because none of the checks reads the view.
- Use it for every batch of items. Current callers:
  - gossip `HopMsg::OfflineItems`
  - controller `RpcBody::OfflineSubmit`
  - control `submit_offline`
  - `state::load_store`
  - `agent::finish_enrollment`

**`offline_hash()`**
- It is cached in `Store.offline_hash: OnceLock<Bytes32>` and computed by `compute_offline_hash`.
- `rebuild()` resets the cache. Any code that changes certs, key_tombs or offline tombstones must therefore go through `rebuild()`.

**Behaviour change in control `submit_offline`**
- A refused item still fails the call: it returns the first error.
- Items accepted before that error are now persisted and pushed.

Test: `store::tests::a_batch_of_offline_items_matches_adding_them_one_by_one`.
