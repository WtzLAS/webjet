`docs/configuration.md` was rewritten (after 0.9.0). Its layout is now:
1. Overview: a table comparing the three places a setting can live (webjetd.toml / network scope / node scope), plus a "Where to put a setting" task table.
2. webjetd.toml: location and restart commands per platform, then every section.
3. The network configuration: working with it, the network scope (`[policy]`, Selectors, Port specs, Magic DNS, seeds, transport priorities, camouflage, padding, compression, limits, controllers), then node scope including `[[proxy]]`.
4. Precedence.
5. Recipes: reverse proxy, gateway, blocked UDP, compression.

Anchors that other docs link to and that must keep existing: `#the-network-configuration`, `#network-scope`, `#node-scope`, `#webjetdtoml`.

Facts verified for the rewrite that are easy to get wrong:
- Node-scope `apply` treats the file as the node's whole configuration, so keys left out are removed (`webjet_tools::config::node_apply`). The network scope merges by section instead.
- A policy rule with no `ports` matches nothing.
- `dead_voter_after_s` is 0 or ≥60 (`membership::MIN_DEAD_AFTER_S`).
- The default DNS TTL is 60.
- Proxy: at most 64 rules per node (`proxy::MAX_RULES`); SNAT source ports 61000–65535; the ingress needs the data role.
