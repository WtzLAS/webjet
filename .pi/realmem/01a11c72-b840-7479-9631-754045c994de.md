**scripts/cargo-mirror.sh source order (changed 2026-10-11 after v0.12.2 CI failure):** `sparse+https://rsproxy.cn/index/` → `sparse+https://mirrors.tuna.tsinghua.edu.cn/crates.io-index/` → `sparse+https://mirrors.ustc.edu.cn/crates.io-index/` → plain crates.io. Every job in .forgejo/workflows/ci.yml and release.yml runs it right after checkout. It writes a `[source.crates-io] replace-with` + `[source.mirror] registry` config plus `[net] retry = 10` between `# --- cargo-mirror.sh begin/end` markers in `$CARGO_HOME/config.toml` (builder image: /usr/local/cargo; rerun replaces the block; refuses a foreign crates-io replacement). Before using a source it probes `<index>/config.json` with curl (connect 5 s, max 10 s) and skips it if silent; each `cargo fetch --locked` is wrapped in `timeout -k 10 $FETCH_TIMEOUT` (default 60 s); up to 3 rounds, 60 s apart; downloads kept between attempts; extra args = additional URLs tried in order. Cargo.lock still says crates.io (checksums verified), so --locked and deny.toml `allow-registry = crates.io` keep working. fuzz.yml does not use it.

**Why the order changed:** all v0.12.2 CI/release jobs (runs 118/119, 8550e6a) failed with "cargo-mirror: no source worked" — every source timed out at 60 s in all 3 rounds while still downloading; runs 116/117 had already needed 2nd-round retries. TUNA mirrors only the index: its config.json has `"dl": "https://static.crates.io/crates"`, so crates come from crates.io via the proxy. Cold workspace fetch on runner box 10.4.0.9 (builder:5, runner proxy env): TUNA 138 s, USTC stalled (0 bytes, 600 s), crates.io 452 s, SJTUG index stale (rc 101), rsproxy.cn 12 s, 4 parallel rsproxy fetches 34 s each; full script 16 s from cold. rsproxy.cn is NOT in the runner NO_PROXY, so it goes via proxy 192.168.31.199:7890 — worked that way. Runner NO_PROXY still lists mirrors.tuna.tsinghua.edu.cn, mirrors.ustc.edu.cn, mirrors.cernet.edu.cn (/root/docker/forgejo-runner/data/runner-config.yml envs + docker-compose.yml dind env, backups *.bak-20261010003333).
