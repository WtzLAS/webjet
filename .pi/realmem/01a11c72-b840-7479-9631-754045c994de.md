Since 2026-10 the CI image is no longer in webjet. It lives in the private org `webj8-internal` (org visibility private; the repo's own `private` flag is false, but anonymous access gets 404 because the org is private): repo `ssh://git@forgejo.wolf109909.top:2222/webj8-internal/webjet-builder.git`, local checkout `~/Projects/webjet-builder` (Dockerfile, build.sh, scripts/macos-sdk.sh, scripts/freebsd-sysroot.sh, README). Image `forgejo.wolf109909.top/webj8-internal/webjet-builder:4`. Reason: it holds Apple's macOS SDK (no redistribution). Forgejo has no per-package visibility; packages follow the owner's visibility, so it must never be pushed under the public `webj8`.
- `./build.sh [--push]` (on a Mac): runs macos-sdk.sh into ~/.cache/macos-sdk, then `docker build --platform linux/amd64 --build-context macos-sdk=…`, passing the shell's proxy vars with 127.0.0.1/localhost rewritten to host.docker.internal. `IMAGE_TAG` lives in build.sh.
- webjet's ci.yml/release.yml/fuzz.yml use `container: image: …webj8-internal/webjet-builder:4` with `credentials: username: ${{ secrets.BUILDER_USER }}, password: ${{ secrets.BUILDER_TOKEN }}` (a webj8-internal member + a read:package token; repo secrets in webj8/webjet).
- webjet keeps its own `scripts/freebsd-sysroot.sh` (freebsd-cargo.sh uses it); keep FREEBSD_VERSION/BASE_SHA256 the same in both repos. `scripts/macos-sdk.sh` and `ci/builder.Dockerfile` were removed from webjet. Old public images webj8/webjet-builder:1/:2 have no SDK.
