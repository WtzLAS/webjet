webjet-app has an admin-only **Config** tab (`crates/webjet-app/src/ui/config.rs`). Its tab enum entry is `Tab::Config`, and `Tab::admin_only()` hides it from members and closes it when an account is demoted. The tab edits the network config and the own config of any node (local or remote; the agent's `node_config` control call takes any node id) as TOML.
- GUI-free pieces: `src/netconfig.rs` (`Doc::network(tree)` / `Doc::node(reply)`, `check`, `plan` → `Plan::ops()`), `src/text.rs` (`Buffer`: multi-line editing, selection, undo/redo, indent, comment toggle; `line_kind` for highlighting). The editor widget is `ui/editor.rs` (uniform_list of canvas-painted lines, Menlo/Consolas mono font, emits `Changed`).
- The apply logic is shared with webjetctl in `webjet_tools::config`: `network_wire`, `camouflage_note`, `network_apply(file, tree, base) -> NetworkApply{version, sections, config, camouflage_key, note}` with `.ops()` (SetCamouflageSecret first when refuse mode needs a new cert), and `node_apply(file, id, name, current) -> Option<NodeConfig>`. webjetctl's `apply_network` / `apply_node` call these.
- Apply in the app: fetch fresh → plan (stale version refused) → sign every op → `Client::submit_all` → poll until the version changes (15 s). It needs a second click (`Confirm::ApplyConfig`). Leaving a config with unapplied edits needs a second click too (`Confirm::Discard(scope)`).
- Tests: `ui::tests::config_tab_is_for_admins` (typing via simulate_input/keystrokes) and live test `admin_edits_network_and_remote_node_configuration`. The live test uses ctl-01 as the remote node, because the member test renames node-03 in parallel. DNS record names must be under the suffix (`x.internal`), otherwise the controller rejects them.
- GPUI 0.2.2 gotcha: `debug_bounds` entries are never cleared between frames. Assert that an element is present, never that it is absent.
