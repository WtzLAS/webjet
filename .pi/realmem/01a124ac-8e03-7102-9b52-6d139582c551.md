User asked (2026-10): default KCP hop retransmission OFF (inner traffic has its own reliability; avoid double retransmits), keep FEC and KCP header (ACKs → raw RTT / BBR delivery), with a transport setting using selectors to re-enable retransmission.

Design: the KCP hop is one in-order KCP stream carrying TLS 1.3 + hop records, so disabling retransmit would stall/kill the hop. Solution: an **unreliable lane** beside the reliable stream on KCP hops: one KCP-headed segment per record piece (sn/ts, acked for RTT/BBR, never retransmitted, delivered on arrival), FEC unchanged below both lanes; peers advertise support, otherwise the reliable stream is used.
- **Lane split by e2e frame type**: every hop (source and relays) classifies a RELAY record by the e2e frame type byte right after the 5-byte relay header (`webjet_core::frames::relay_unreliable` / `ftype::unreliable`); that byte is outside the e2e encryption. NO new hop record type — a frame that crossed a TCP hop goes on the lane again at the next KCP hop, and older relays need nothing new. Unreliable types: DATA/DATA_LZ4/PROXY/PROXY_LZ4/MCAST/PROBE/PROBE_ACK; RPC/RPC_ZSTD/HANDSHAKE/PUNCH/CLOSE/GROUPS reliable.
- **Selector scope = sending node per hop**: `retransmit` in `[[transport.override]] select=[…]`, plus network/node scope setting. Each relay applies its own `retransmit` setting, not the source's; a matched node retransmits on every KCP hop it sends on.
- **Per-hop AEAD** for the lane: keys from the hop TLS exporter, KCP sn as nonce, replay window.
- **Oversize frames: split with no retransmit** (pieces; losing one loses the frame) → tun MTU constraints, see below.

Implemented 2026-10 (uncommitted at first; docs call it 0.12.0). Architecture §17.5.1, configuration.md "Retransmission (`transport.retransmit`)". Implementation map:
- `crates/webjet-net/src/kcp/lane.rs`: `Lane` with pieces as KCP segments of new commands `CMD_UPUSH=85`/`CMD_UACK=86` (proto.rs). `frg` holds the remaining piece count, top bit 0x80 marks the first piece. `sn` is the low 32 bits of a u64 counter (`extend`). ChaCha20-Poly1305 via `SessionKey::seal_in_place`/`open_in_place` (webjet-core frames.rs) with the KCP header as AAD, plus a ReplayWindow. `lane::MTU=1354`, `PIECE=1314` (= 1280 inner + 29 e2e + 5 relay), at most 64 pieces. Incomplete frames are dropped after 1 s.
- proto.rs `flush` interleaves lane pieces with stream segments oldest first, within the pacer budget, outside the send window. Lane UACKs feed rtt_samples and delivered.
- kcp/mod.rs: `LaneIo {tx, rx, start(keys)}` in `KcpConn`; the session task gets `LaneTask` (keys via oneshot). Exports `LANE_PIECE`, `LANE_MAX_RECORD`, `LANE_INNER_MAX` (=1280, const-asserted). `KcpStats.lane_{tx,rx,incomplete}`.
- hop.rs: the KCP dialer offers ALPN `webjet/1+lane` (`tls::ALPN_HOP_LANE`) before `webjet/1`. On a match, `start_lane` exports 64 bytes with label `webjet kcp lane v1` (first half = client→server). `Established.lane: Option<LaneIo>`.
- webjetd node.rs: `Hop.lane: bool`. The writer's `on_lane()` sends RELAY records whose e2e type passes `frames::ftype::unreliable` to the lane, with the 4-byte record header stripped, unless `Node.retransmit`. A `lane_reader` task feeds `circuit::on_relay_frame`.
- Config: schema fields `TransportConfig.retransmit`, `PriorityOverride.retransmit`, `NodeConfig.retransmit` (bool = null); `View::retransmit(node)` resolves node → first override that sets it → network → false. Refreshed in `transport::apply_limits` (on HeadChanged). TOML: `[transport] retransmit`, `[[transport.override]] retransmit` (priority is now optional, but an override must set one of the two), node scope `transport.retransmit`.
- Output: `local status.retransmit`, `local peers[].lane` {tx_records, rx_records, incomplete}, LinkMetrics.lane_*, Prometheus `webjet_link_lane_*`.
- tun MTU: default from `LANE_INNER_MAX`; webjetd refuses < 576 and warns > 1280 (`config::mtu_warning`).
- Tests: `kcp::tests::the_lane_sends_once_and_fec_repairs`, lane.rs unit tests, `statemachine retransmit_network_overrides_and_node`, `config::tests::tun_mtu_bounds`. Local-net check: pings count on `lane`; with node-02 retransmit=true, node-02's lane tx stays flat while node-03's replies still arrive on the lane.
- local-net pitfall: webjetctl account commands need `WEBJET_ACCOUNT_PASSPHRASE=acct-pass WEBJET_KEYS=<workdir>/keys --account alice`. macOS has no `timeout` command.
