webjet-app one-line fields (`crates/webjet-app/src/ui/field.rs`, `Field`) support a cursor and selection by mouse (click, drag, shift-click, double-click word, triple-click all) and keys (arrows, shift/⌥/⌘ variants, ⌥/⌘ Backspace, ⌥ Delete, ⌘A/C/X/V). GUI-free editing logic is `crate::text::Line` (byte offsets, `Zeroizing<String>`, no undo so passphrases leave no copies; `opaque` = secret field: word moves/double click take the whole text, ⌘C/⌘X do nothing). Word helpers `word_left_in`/`word_right_in`/`word_around` in text.rs are shared with the multi-line `Buffer` (config editor, ui/editor.rs). Field renders the text as a normal child plus an absolute `canvas` behind it that shapes the shown string (`*` per char when secret, mapped via `shown_offset`/`text_offset`), paints selection + caret, stores `(left, ShapedLine)` for hit testing, and while dragging registers window-wide MouseMove/MouseUp listeners. Unhandled keys (Enter, Tab, Escape without selection) bubble to the form (sign-in Enter). Test: `ui::field::tests::text_can_be_selected_with_the_mouse_and_keys`; docs/app.md describes the keys.

Proptests in `crates/webjet-app/src/text.rs` tests::props (proptest, webjet-app dev-dependency): `buffer_edits_keep_offsets_on_characters` runs random edits (insert of multi-byte/combining/CR pieces, moves, set_cursor at any byte, select_word, indent/outdent/comment, undo/redo) and checks the cursor, selection, `selected_in_line` and `line_kind` key offsets stay on char boundaries, no line contains '\n'/'\r', and undoing everything restores the start text. `line_edits_keep_offsets_on_characters` does the same for `Line` (opaque too). The test found that `split` (Buffer::new/set_text) kept a lone '\r' inside a line; it now folds "\r\n" and '\r' like `insert`. Mutation check: removing `clamp`'s boundary loop fails the test. Deep run: `PROPTEST_CASES=30000 cargo test --release -p webjet-app --lib text::tests::props`.
