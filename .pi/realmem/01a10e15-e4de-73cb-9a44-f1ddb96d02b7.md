Added after v0.7.0. EndpointRecord, LinkStateAdvert and AttachmentRecord now carry an appended field `protocol: uint16`. `crates/webjet-core/src/protocol.rs` defines `GOSSIP_PROTOCOL` (2) and `MIN_GOSSIP_PROTOCOL` (1). A record without the field is protocol 0; for an EndpointRecord it is inferred from `software`: `webjetd/0.7.x` counts as 1, anything older as 0. So 0.6.x and older are ignored.

`gossip::refuse_old_protocol` is called inside `accept_record`:
- An EndpointRecord below the floor puts the node in `Records.outdated` (software, seq, expiry, raw) and drops the node's endpoints, LSA and attachment records.
- Field-less LSAs and attachments are refused while their node is marked outdated.
- A newer EndpointRecord at or above the floor clears the mark.
- `on_lookup` also returns the outdated EndpointRecord, so edge nodes learn the version.

`topology` JSON now has per-node `software` (e.g. "0.7.1") and `outdated`. `endpoints` is always a list. 0.7.0 agents sent `"endpoints": null` for nodes without an EndpointRecord, which broke webjet-app with "links unavailable: … invalid type: null". The app model now has a `nullable` deserializer. The Nodes graph labels each vertex with its version and dims outdated ones.

Raise `MIN_GOSSIP_PROTOCOL` / `GOSSIP_PROTOCOL` only for incompatible gossip changes, and say so in the release notes, because upgraded nodes then stop routing through the old ones.

Verified with local-net plus a v0.6.1 webjetd built in a git worktree (`git worktree add /tmp/webjet-061 v0.6.1`).
