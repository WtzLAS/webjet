Design the user chose (2026-10-05) over three alternatives: a webjetctl.toml CLI config file, picking the account automatically by role, or only documenting WEBJET_ACCOUNT. Resolution order is `--account` > `WEBJET_ACCOUNT` > the `default` file in the key directory > the only key.
- Library helpers in `crates/webjet-tools/src/lib.rs`: `DEFAULT_ACCOUNT_FILE = "default"`, `default_account(dir)`, `set_default_account(dir, Option<&str>)` (refuses a name without `<name>.key`; `None` removes the file), and `pick_account(dir, given)`.
- `pick_account` errors if the default names an account without a key. With several keys and no default, the error mentions `account use`.
- `load_account` in webjetctl uses `pick_account`.
- CLI: `webjetctl network account use [NAME] [--clear]`. With no argument it shows the current choice and notes when `--account`/`WEBJET_ACCOUNT` overrides it.
- `network account list` has a HERE column: `*` = the account it signs as, `key` = other accounts with a key here.
- Docs: ops guide "Running webjetctl", docs/docker.md bootstrap example.
- Test: `account_selection` in lib.rs (webjet-tools now has dev-dependency tempfile).
