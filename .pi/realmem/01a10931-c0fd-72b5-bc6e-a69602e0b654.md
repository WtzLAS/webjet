webjet-app has a Merkle tab (crates/webjet-app/src/ui/merkle.rs, GUI-free logic in src/merkle.rs: MerkleWire, Merkle::new rebuilds the sparse Merkle tree from leaves and checks it against the signed head, decodes leaves via webjet_core::leaf::decode, Names maps keys/ids to "admin alice"/"the root key"/"node x", LogPage paging/refreshed).

Data sources (added after 0.4.4):
- `merkle` control command (crates/webjetd/src/control.rs `fn merkle`): every leaf (kind, hex key, b64 bytes), head, genesis keys, SigningKeyCerts (issuer admin or root, valid), key tombstones. `source` = "controller" (own state machine, may be ahead of head) or "head". Fetched only while the Merkle tab is shown (`Client::snapshot(metrics_all, merkle)`), stored as `Rc<Merkle>` in WebjetApp, not in the per-frame Snapshot clone.
- `log` control command → `RpcBody::GetLog { request: Signed(LogRequest) }` (msg_type LOG_REQUEST = 27, schema in webjet.fbs; GetLog/LogReply/LogRecord/LogLeaf in wire.fbs) → `Controller::log` (crates/webjetd/src/controller/audit.rs: check_request = valid admin, current key, issued_at ±5 min; window ≤200 entries; summarize omits EntryRandom PSK). Controller keeps `descriptions: BTreeMap<index, Outcome.description>` for entries since the last snapshot (pruned in compact). Client: `ops::log_request(account, before, limit)` (no op_seq), `Client::log`.
- Log starts with index 1 = leader's Noop, 2 = Genesis (signed by root key) on an uncompacted log.
Tests: audit unit tests, merkle.rs unit tests, tests/live.rs `merkle_tree_and_operation_log_from_a_live_network`, fixture tests/fixtures/node-02.json now includes "merkle" (regenerate by querying each control command of node-02 with `scripts/local-net.sh 4` running; JSON indent=1 sort_keys).
