Control channel, since P4 refactor (after 0.7.1): `crates/webjetd/src/control.rs` became `control/mod.rs` (serve, read_request, handle, COMMANDS access table, submit_op/submit_signed/forward_offline, client::call) + `control/request.rs` (`pub enum Request`, `#[serde(tag = "cmd", rename_all = "snake_case")]`; binary args base64 via `with = "base64"`, node ids hex `Option<Bytes32>` via `hex_id`; `to_json()`, `name()`) + `control/commands.rs` (`run(n, Request)` dispatch, one fn per command; `status` re-exported as `control::status`).
- `handle(n, Value)`: checks `cmd` against COMMANDS first (error "unknown command X" — webjet-app matches it to detect old agents; unlisted commands rejected), then `serde_json::from_value::<Request>` ("bad arguments for X"), then `commands::run`. COMMANDS entries carry `Access::{Read, Signed, Capability}`; unit tests parse `handle`'s match arms from source (`include_str!`) and require equality with the table, pinning non-Read set to submit_op, submit_offline, submit_signed, redeem_self, log.
- `client::call(path, &Request)` used by webjetctl (`call(cli, Request::…)`), webjet-app `Client::call/get(Request)`, agent.rs enroll (`RedeemSelf`).
- Wire form is exactly the old hand-built JSON (test `the_wire_form_is_the_old_hand_built_json`) so mixed versions interoperate; new args must be optional.
- Limits: `MAX_REQUEST` 4 MiB per line (`read_request`), `MAX_CONNECTIONS` 64 (semaphore; extra get an error line). Ping `count` saturates to u16 instead of wrapping. Docs: docs/development.md "Agent tasks" and "The control channel".
- Adding a command: variant in Request + COMMANDS entry (+ state-changing test list if not Read) + arm in commands::run.
- Fuzz target `control_request` (round trip).

Task supervisor `crates/webjetd/src/tasks.rs`: `Supervisor` held as `Node::tasks`. Long-running loops start with `n.tasks.service(name, fut)` / `service_result` (ending at all — return, error, panic — is fatal: `run_until` logs it, calls `abort_all`, persists, cleans up, returns Err so systemd/launchd/Docker restart the agent) or `n.tasks.oneshot(name, fut)` (only panic is fatal; used for start-dataplane, port-mapping, control-socket, metrics-endpoint). Services: controller, watch-control-role, gossip, e2e, paths, metrics, health, punch, connections, secrets, tls-listener, kcp-accept, anytls-listener, tun-writer, tun-reader, dataplane-refresh. Per-connection tasks stay `tokio::spawn`. `install_panic_hook` (called from `logging::init`, Once) logs panics via tracing. A new agent-lifetime loop must use `n.tasks.service`, not `tokio::spawn`, and must never return in normal operation.
