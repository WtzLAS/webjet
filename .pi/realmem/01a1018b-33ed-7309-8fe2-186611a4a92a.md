`crates/webjetd/src/controller/raft.rs` is a pure Raft core (time passed in, seeded RNG, `Storage::mem()`/`disk()`), with pre-vote, check-quorum, single-server membership read from the log via `classify_entry` in controller/mod.rs (`config_at(idx)` must equal the state machine's membership; mismatch halts). Tests in `raft_tests.rs`: targeted scenarios + randomized simulator checking election safety, log matching, leader completeness, state-machine safety, config agreement, liveness after healing. Commands: `cargo test -p webjetd --lib raft`; soak `WEBJET_RAFT_SEEDS=2000 cargo test --release -p webjetd --lib randomized`; `WEBJET_RAFT_TRACE=1` prints seeds; `scripts/raft-mutations.py` re-injects 10 classic bugs (exit 2 = pattern no longer matches source → update pattern). Real bugs found: (1) a leader that appended its own demotion then lost leadership could deadlock a 2-voter cluster — fix `can_campaign()` lets voters of the committed config campaign, votes counted against latest config; (2) a non-voter leader never stepped down (check-quorum must apply regardless of voter status).

Controller lock order (documented on `struct Controller`, controller/mod.rs): `apply_lock` → `raft` → `machine` → node store. Never take `raft` while holding `machine` (status() used to, deadlocking against propose()). `Controller::is_halted()`; `apply_committed` and `maybe_sign_head` return early when halted; `applied` advances only after the membership check.

Raft `Storage` methods (`save_meta`, `append`, `rewrite`, `load_meta`, `load_log`) return Result. A failed write sets `Raft.failed` (fail-stop): `handle`/`tick`/`offer_snapshot` send nothing, `propose` → `ProposeError::Storage`; `apply_committed` sees `raft.failed()` and halts the controller. Restart reloads. Tests use `MemStore.fail_writes = true`. Opening is strict: damaged meta.json, bad `voted_for`, a damaged log record followed by valid ones, or an index gap (`contiguous` returns Err) fail `Raft::new`; only missing files = fresh start; only a torn tail is truncated. Disk log: log.bin is length-prefixed records appended with `append` (O_APPEND + sync_data); a crash mid-append leaves a torn final record — `load_log` now `set_len`s the file to the last complete record (warns "raft log: torn tail of N bytes dropped") instead of only skipping it, since skipped torn bytes caused post-restart appends to land behind them and the next restart to silently lose acknowledged entries. Covered by `disk_storage_roundtrip` in raft_tests.rs (append after a torn tail, then reload → 5 entries). Mutation-script note: "vote not persisted" pattern now matches `let r = self.storage.save_meta(...)`. (2026-10 Phase 1 fixes.)
