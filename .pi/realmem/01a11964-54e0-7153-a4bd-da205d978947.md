`docker/multicast-test.sh` (image `webjet:test`; build with `docker build --target test -t webjet:test .`; `KEEP=1` leaves the containers running, `clean` removes them) runs ctl-01 plus g-1/g-2/g-3 (`tag:game`) and o-1 (`tag:office`) on subnet 172.30.8.0/24. It uses `docker/mcast.py` (listen/send/pong). The test image now includes python3-minimal. Passed on 2026-10-08, ~1.5 min.

Pitfalls:
- `webjetctl network node enroll --tags` needs the `tag:` prefix (`tag:game`).
- Ping-wait loops need a `sleep 1`, because "host unreachable" comes back instantly while routes are coming up.
- Linux delivers a host's own broadcasts back to it, so reflector/repeater scripts must skip their own source address. Otherwise they loop locally, at 46k/s.
- The pool directed broadcast (10.7.255.255) looks like unicast to `packet::is_unicast`. `Dataplane::outbound` must check `multicast::is_pool_broadcast` too, or it ends up in `route()` → no_route + ICMP.
- A loop that mutates its payload dies out once the budget drops one copy, because each reflection chains on the previous one. It isn't sustained at the budget rate.
