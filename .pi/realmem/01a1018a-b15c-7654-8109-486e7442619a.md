Before committing in Webjet run `cargo fmt`, `cargo clippy --workspace --all-targets -- -D warnings`, the same with `--no-default-features`, and `cargo test --workspace`. Everything must be warning-free, tests included: the user requires it, and CI (`.forgejo/workflows/ci.yml`) enforces it with `-D warnings`.

Workspace lints warn on `clippy::unwrap_used`/`expect_used`; `clippy.toml` allows them in tests. Parse untrusted bytes with the checked readers in `crates/webjet-core/src/bytes.rs` (return None); sort floats with `total_cmp`. Generated `webjet-proto/src/generated.rs` is `#[rustfmt::skip]` and lint-allowed in lib.rs; never hand-edit it.

Platform-only code (`cfg(target_os = "linux")`, `cfg(windows)`) isn't checked by clippy on macOS.

**Linux clippy/tests from macOS:**
```
docker run --rm -v "$PWD":/src -v webjet-cargo-registry:/usr/local/cargo/registry -e CARGO_TARGET_DIR=/src/target-linux -w /src rust:1-bookworm sh -c 'rustup component add clippy >/dev/null 2>&1; apt-get update -qq >/dev/null && apt-get install -y -qq cmake clang libclang-dev >/dev/null 2>&1; cargo clippy -q -p webjetd -p webjet-core --all-targets -- -D warnings && cargo test -q -p webjetd --lib -- <filters>'
```
Takes several minutes: run via bg_run. `target-linux/` is the Linux build dir. (webjet-app needs GPUI's X11/Wayland/Vulkan packages and is excluded.)

**Windows (webjetd) from macOS:** `cargo check -p webjetd --no-default-features --target x86_64-pc-windows-gnu`. The default `anytls` feature builds boring-sys, which fails to cross-compile with "stdlib.h not found".

**Intel macOS:** `--target x86_64-apple-darwin` works.

pi-lens's `rust-unwrap` tree-sitter rule also flags unwraps inside `#[cfg(test)]` modules; those are false positives, clippy is authoritative.
