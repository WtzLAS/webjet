Admins can't create admins. `put_account` in `crates/webjet-core/src/statemachine.rs` refuses with "admins can't create admins", and "only the root may change an admin account". Procedure (docs/webjet-operations-guide.md runbook 13, checked by docker/runbook-test.sh):
1. The person runs `webjetctl network account keygen --name carol --pub-out carol.pub`.
2. Offline: `webjetctl root --dir … admin sign --name carol --key carol.pub --out carol.account`.
3. On any enrolled node: `webjetctl network submit carol.account`. It needs no account key; the agent routes it as a SubmitRoot / RootAccountEntry.

The same steps with an existing account's `.pub` make that account an admin. It keeps its ID and devices.

The account ID comes from the `.pub` and the name from `--name`. So:
- The same `.pub` under a new name renames the account.
- An existing name with another key is refused: "account name X is taken".
- Re-submitting the same file is refused: "account version must increase" (versions are now_ms timestamps).

Verified on a local net (scripts/local-net.sh) on 2026-10-05.

Pitfall: leftover local-net agents (e.g. /tmp/wj-acct) occupy port 17001. A new `scripts/local-net.sh` then fails with "controller did not start" (the log says "bind 127.0.0.1:17001: Address already in use"). Check `pgrep -fl 'webjetd -c /tmp/'` and stop them with `scripts/local-net.sh stop <dir>`.
