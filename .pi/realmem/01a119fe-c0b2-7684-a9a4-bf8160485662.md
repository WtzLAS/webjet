FreeBSD/OPNsense prep (2026-10, user wants to deploy to OPNsense later), cfg `target_os = "freebsd"`:
- tun (crates/webjetd/src/dataplane.rs `start`): tun-rs on FreeBSD only accepts `tunN` names (opens /dev/tunN). For other configured names (default `webjet0`) webjetd builds without a name and then calls `dev.set_name` (SIOCSIFNAME). Before building it runs `platform::destroy_stale_tun(name)`: FreeBSD tun interfaces outlive a killed process, so a leftover that is listed by `ifconfig -g tun` and whose `ifconfig <name>` output has no "Opened by PID" gets `ifconfig <name> destroy`. `platform::is_tun_unit` detects `tunN`.
- routes (platform.rs `route_cmd`): uses the same BSD `route -q -n add -inet[6] NET -interface DEV` as macOS. `add_route` falls back to `route change` on macOS/FreeBSD when the route already exists (tun-rs's associate_route already adds the pool prefix route) — `bsd_change`.
- split DNS: not configured on FreeBSD; it warns once (OPNsense Unbound query forwarding by hand). Gateway NAT and reverse proxy stay Linux only.
- multicast groups: the macOS `getifmaddrs` FFI (`groups_os`) is shared with FreeBSD (struct ifmaddrs has the same layout).
- capture (capture.rs): the macOS BPF module is shared (`mod os` cfg any(macos, freebsd)). ioctl numbers are computed by `ioc()` (_IOC) with const asserts against the 64-bit values. FreeBSD opens the cloning `/dev/bpf` and sets `BIOCSDIRECTION` (=119, `_IOW('B',119,u_int)`; 118 is GDIRECTION) to BPF_D_OUT. `bpf_records(buf, &BpfHdr)` takes the header layout: macOS caplen@8/hdrlen@16/align 4; FreeBSD 64-bit caplen@16/hdrlen@24/align 8 (from libc::bpf_hdr offsets, const-asserted). `NOT_CAPTURED_IFS` skips utun/tun/tap/ipsec/enc/ovpn/wg/ppp/gif/gre/stf/awdl/llw/pflog/pfsync.
- nat.rs TUNNEL_PREFIXES gained `ovpn`, `enc`, `gre`.
- Docs: architecture §19.1 bullet "FreeBSD (OPNsense) is being prepared", §9.5.1/§9.5.2 mention FreeBSD; configuration.md `[tun] name` row.
Not done yet: service/rc.d, webjetup/install.sh/release targets, keystore (falls to File backend), tcp_info/TCP tuning in webjet-net (FreeBSD falls to the no-op path).
