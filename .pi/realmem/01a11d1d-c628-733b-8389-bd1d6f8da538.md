Webjet uses patched copies of gpui 0.2.2 and gpui_media 0.2.2 in `vendor/gpui` and `vendor/gpui_media`, wired in through `[patch.crates-io]` in the workspace Cargo.toml (`exclude = ["vendor"]`). The patches let webjet-app cross-compile from Linux (builder:5) for macOS (commit b802713) and Windows (commit b851b22). Every changed place has a `Webjet:` comment (`grep -rn "Webjet:" vendor`); the full list is in `vendor/README.md`.\n\nPatches to redo after copying a new gpui (copy `build.rs`, `Cargo.toml`, `src/`, `resources/`, `LICENSE-APACHE` and `README.md` over the vendored copy, then `cargo update -p gpui -p gpui_media`):\n1. **gpui/build.rs `main`**: pick steps by `env::var("CARGO_CFG_TARGET_OS")`, not `#[cfg(target_os)]` (build machine's OS). "macos" → `macos::build()` (plus WGSL check if feature macos-blade), "windows" → `windows::build()`, else `check_wgsl_shaders()`. Remove the `#[cfg]` from `mod macos`, `mod windows` and `check_wgsl_shaders`.\n2. **gpui/build.rs `mod windows`**: no `compile_shaders`/fxc.exe/`shaders_bytes.rs`, only `embed_resource()`: writes a copy of `resources/windows/gpui.rc` to OUT_DIR, replacing `"resources/windows/gpui.manifest.xml"` with the absolute path (forward slashes) and asserting it's present. Reason: cross-compiling, llvm-rc resolves the relative path against OUT_DIR ("file not found").\n3. **gpui/src/platform/windows/directx_renderer.rs `mod shader_resources`**: always compile at run time with `D3DCompile` (d3dcompiler_47.dll, part of Windows), never precompiled bytes. Sources are `include_str!` of shaders.hlsl, color_text_raster.hlsl and alpha_correction.hlsl, with `#include "alpha_correction.hlsl"` inlined by `replacen`. Flags: `D3DCOMPILE_OPTIMIZATION_LEVEL3` in release (fxc /O3), `DEBUG|SKIP_OPTIMIZATION` in debug. Profiles vs_4_1/ps_4_1, entry points `<module>_vertex`/`_fragment`. `RawShaderBytes` always holds an ID3DBlob; `ShaderModule::as_str` is no longer debug-only.\n4. **gpui/src/platform/windows/destination_list.rs**: replace ICU `u_strlen` (from `Win32::Globalization`) with `buffer.iter().position(|&c| c == 0)`. Otherwise the exe imports icuuc.dll (only Windows 10 1903+; Wine lacks it) and fails to load.\n5. **gpui/Cargo.toml**: bindgen, cbindgen, naga and embed-resource become unconditional `[build-dependencies]` (upstream had them under target cfgs). Delete the `[[example]]`/`[[test]]` targets (sources aren't copied).\n6. **gpui_media/build.rs**: one `main` returning early unless `CARGO_CFG_TARGET_OS == "macos"`, instead of two `#[cfg]` mains. On Linux, `xcrun --show-sdk-path` is answered by the scripts/macos-cargo.sh shim.\nAlso in webjet-app (not vendored): main.rs has `#![cfg_attr(not(debug_assertions), windows_subsystem = "windows")]`.\n\nVerification recipe: run `.pi/tmp/app-all.sh`-style checks in builder:5 on root@10.4.0.9: `cargo xwin build --release -p webjet-app`, xwin/macos/freebsd clippy with -D warnings, `cargo test -p webjet-app`, `scripts/deny.sh`. Then run the exe under Wine (scottyhardy/docker-wine:stable-9.0 with `--entrypoint sh`, since its entrypoint drops root; Xvfb; `winetricks -q d3dcompiler_47 corefonts`; `GPUI_DISABLE_DIRECT_COMPOSITION=1`, because Wine lacks CreateSwapChainForComposition). Wine limits: its own d3dcompiler (vkd3d) can't parse shaders.hlsl (syntax error line 516), and its DirectWrite has no GetFontSet, so `select_font` panics at direct_write.rs:471 — the app has never shown a window under Wine. With native d3dcompiler_47 the DirectX renderer (all shaders) is created. As of b851b22 the app has not been run on real Windows. `scripts/gpui-vendor-check.sh` (pre-commit hook) warns when crates.io has a newer gpui.\n\nmacOS cross-builds: `scripts/macos-cargo.sh <aarch64|x86_64>-apple-darwin build -p webjet-app` works in builder:5 (SDK 26.5, minos 11.0); release.sh ships `webjet-app-<tag>-<apple target>.tar.gz`; CI's macOS clippy includes webjet-app.
