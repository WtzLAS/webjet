gpui 0.2.2 and gpui_media 0.2.2 build scripts used `#[cfg(target_os = "macos")]` (the build machine's OS), so cross-compiling webjet-app for macOS on Linux skipped dispatch_sys.rs, stitched_shaders.metal and the CoreMedia bindings. Since commit b802713, `vendor/gpui` and `vendor/gpui_media` hold copies whose build.rs checks `CARGO_CFG_TARGET_OS`. vendor/gpui/Cargo.toml makes bindgen, cbindgen and naga unconditional build-dependencies and drops the example/test targets. They are wired in through `[patch.crates-io]` in the workspace Cargo.toml, with `exclude = ["vendor"]`. vendor/README.md describes how to update them; every changed place has a `Webjet:` comment. With this, `scripts/macos-cargo.sh <aarch64|x86_64>-apple-darwin build -p webjet-app` works in builder:5 (SDK 26.5, minos 11.0). release.sh ships `webjet-app-<tag>-<apple target>.tar.gz`, and CI's macOS clippy includes webjet-app. Windows is still not built: gpui's Windows release build needs fxc.exe (Windows SDK) for its HLSL shaders, and its windows::build() is also host-cfg'd.
