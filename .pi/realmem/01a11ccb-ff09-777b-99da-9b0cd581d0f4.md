libc 0.2.190 removed the Linux constant `libc::ENOATTR`. `xattr` 0.2.3 still uses it and was pulled in only by gpui 0.2.2 → gpui_http_client 0.2.2 → zed-async-tar (default feature `xattr`), so webjet-app didn't build for Linux and libc used to be pinned at 0.2.189. Fix (2026-10): `vendor/gpui_http_client` (a copy of the crates.io 0.2.2 `Cargo.toml`, `src/`, `LICENSE-APACHE`) with `default-features = false` on its `async-tar`/zed-async-tar dependency (marked with a `Webjet:` comment), wired in through `[patch.crates-io] gpui_http_client = { path = "vendor/gpui_http_client" }`. Only `github_download` uses the tar crate, and gpui never calls it. The pin is gone: libc is 0.2.190, xattr 1.6.1 is the only xattr left, and `cargo update` is safe. `scripts/gpui-vendor-check.sh` now also checks gpui_http_client. Documented in vendor/README.md and docs/development.md. Verified in builder:5: Linux workspace clippy, xwin/FreeBSD/macOS clippy of webjet-app, `cargo test -p webjet-app` and deny.sh all passed. When updating the vendored copy, set default-features = false again.
