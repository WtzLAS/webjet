libc 0.2.190 removed the deprecated Linux/Android constant `libc::ENOATTR` (it was an alias for ENODATA). xattr 0.2.3, pulled in only by gpui 0.2.2 → gpui_http_client → zed-async-tar, still uses it, so `cargo build -p webjet-app` for *-linux-gnu fails with "cannot find value `ENOATTR` in crate `::libc`". macOS and FreeBSD are not affected because there ENOATTR is real. Fix used (2026-10): `cargo update -p libc --precise 0.2.189`. Keep libc at 0.2.189 until gpui drops xattr 0.2 or libc brings the constant back; a plain `cargo update` would bump it again, and CI's Linux webjet-app clippy/build would break.
