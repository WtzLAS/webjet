Since the change after v0.11.6 (crates/webjetup/src):
- `webjetup install/upgrade` first calls `hand_over` (main.rs): if the target release's webjetup (downloaded + sha256-checked, or `<--from dir>/webjetup`) reports a newer version than the running one, it runs it with the same argv and env `WEBJETUP_HANDED_OVER=1` (prevents loops) and exits with its code. So every release is installed by its own webjetup, which installs itself (`install_self`).
- `install()` only replaces programs (returns false when the version is already installed: "already installed … setting it up again"); then always `setup_system` (retired programs, install_self, dirs, Windows ACL/PATH/Start-menu shortcut `ProgramData\Microsoft\Windows\Start Menu\Programs\Webjet.lnk`, Linux user, default config), signer::setup, remote::setup, start_after_install, `remote::note_setup`.
- Service definitions go through `system::write_if_changed` (systemd unit, launchd plists, FreeBSD rc.d via `freebsd::install` → bool) and `system::windows_service` (sc.exe `qc` compared, `create` or `config` to update; description/failure always reset). Restarts follow `system::Start {No, Yes, IfChanged}`.
- Hidden `webjetup setup [--start yes|no|if-changed]` = everything but programs/enroll. The remote upgrade helper, after replacing programs + webjetup, runs the NEW `webjetup setup --start yes` (falls back to its own restart if the new one lacks `setup`).
- `<spool>/setup-version` holds the webjetup version that last set up the node; `apply-upgrade` (incl. `--recover`, which systemd runs as ExecStopPost with the NEW binary) calls `set_up_if_outdated` → `setup(IfChanged)` once per version. This fixes nodes remotely upgraded by an old (≤0.11.6) helper.
- Linux unit capabilities: `system::AGENT_CAPABILITIES` = CAP_NET_ADMIN CAP_NET_BIND_SERVICE CAP_NET_RAW (NET_RAW for multicast capture AF_PACKET). CapAmb hex 0x3400.
- `layout::OPTIONAL_PROGRAMS = ["webjet-app"]`: installed when the archive has it, removed otherwise; `all_files()` = wanted + optional (used for extract/backup/remove).
- Windows install: `scripts/install.ps1` (`irm …/install.ps1 | iex`, args via `& ([scriptblock]::Create((irm …))) --enroll …`; throws instead of exit), published by scripts/release.sh with install.sh.
