`docs/webjet-operations-guide.md` was rewritten against the real CLIs (webjetup, webjetd, webjetctl, webjet-root, webjet-signer) and is tested by `docker/runbook-test.sh` (runbooks 1, 2, 3, 5, 7, 8 on systemd containers installed via install.sh; `RELEASE=vX PORT=8443` uses a published release, without RELEASE it builds the checkout and serves fake release pages). It passed against the published v0.2.2 on port 8443.

Facts the guide relies on: a node listens only where `[listen]` says (no default listener); the first controller enrolls its own node through its running agent, so the guide uses `webjetd enroll` there; listening on 443 as user `webjet` needs CAP_NET_BIND_SERVICE in the unit (after v0.2.2); a revoked node disappears from `webjetctl node list` rather than showing `VALID false`; `webjet-root node revoke` takes the node id (hex) from `webjetctl node show`; `webjet-root admin revoke` and `account revoke` take the account's `.pub`; `webjet-signer` exists but has no ready-made service file; `force-new-cluster` and snapshot export/restore are not implemented (runbook 11 says so).
