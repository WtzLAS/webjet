`docs/webjet-operations-guide.md` is now organised as chapters/sections referenced as "section N.M" (code comments say "ops guide N.M"); the old "runbook N" numbering is gone everywhere (README, docs, code comments, runbook-test.sh). Chapters: Ch.1 Accounts — 1.1 create member, 1.2 create admin (root-signed), 1.3 revoke account, 1.4 replace lost/compromised account key; Ch.2 Nodes — 2.1 bootstrap, 2.2 data node, 2.3 relay, 2.4 control node + promote, 2.5 gateway to a LAN, 2.6 revoke node, 2.7 re-key/replace node, 2.8 replace lost voter, 2.9 retire controller; Ch.3 Maintenance — 3.1 PSK, 3.2 camouflage cert, 3.3 upgrade, 3.4 schema-change release (StateVersion), 3.5 network config, 3.6 node config, 3.7 tags/roles/ip/owner, 3.8 backups; Ch.4 Emergency — 4.1 majority of voters lost, 4.2 revoke without controller majority (emergency-key tombstones + `local inject`), 4.3 compromised controller, 4.4 compromised admin, 4.5 offline computer lost / root keys exposed (no root key rotation exists → rebuild). Mapping from old runbook numbers: 1→2.1, 2→1.1+2.2, 3→2.3, 4→2.4, 5→2.8, 6→3.1, 7→3.2, 8→1.3/2.6/4.2, 9→2.7, 10→2.9, 11→3.4, 12→4.1, 13→1.2. Additional facts: there is no camouflage-cert-expiry alarm in the code (guide says check with openssl); refuse-mode self-signed cert lasts 825 days; `network config set dns.record.0 '{…}'` fails when the array is empty (set the whole array instead); seeds must be RELAY or CONTROL nodes. The guide is still tested by `docker/runbook-test.sh`, which runs the covered scenarios on systemd containers installed via install.sh; `RELEASE=vX PORT=8443` uses a published release, without RELEASE it builds the checkout and serves fake release pages; run with `WEBJET_TEST_DNS=1.1.1.1 docker/runbook-test.sh` on this Mac. Since 0.4.0 it also checks `network config check/apply/show`, that a stale file is refused, and policy tests via `network config get policy.test.0.expect`. CLI facts still relied on: 0.4.0 layout (`webjetctl network …`, `webjetctl local …`, `webjetctl root …`, `webjetd signer`); a node listens only where `[listen]` says; the first controller enrolls its own node via `webjetctl local init --genesis` (roles `data,relay,control`); admin-signed certify via `webjetctl network controller certify ctl-01` (root-signing via cert-request is the alternative); giving an admin a new key or revoking an admin voids the controller certs that admin signed — re-certify them with another admin first; after `controller remove`, the control role is taken away (refused while the node is a Raft member); listening on 443 as user `webjet` needs CAP_NET_BIND_SERVICE in the unit; a revoked node disappears from `webjetctl network node list` rather than showing `VALID false`; `webjetctl root node revoke` takes the node id (hex) from `webjetctl network node show`; `webjetctl root admin revoke` and `root account revoke` take the account's `.pub`; `webjetd signer` has no ready-made service file; `force-new-cluster` and snapshot export/restore are not implemented (guide 4.1 says so).
