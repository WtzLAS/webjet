`docs/webjet-operations-guide.md` is written against the real CLIs (webjetup, webjetd, webjetctl; 0.4.0 layout: `webjetctl network …`, `webjetctl local …`, `webjetctl root …`, `webjetd signer`) and is tested by `docker/runbook-test.sh` (runbooks 1, 2, 3, 4, 6, 8, 9 on systemd containers installed via install.sh; `RELEASE=vX PORT=8443` uses a published release, without RELEASE it builds the checkout and serves fake release pages). It passed against the published v0.2.2 on port 8443. It does NOT run runbook 10 (retiring a controller's signing key) or the runbook 10 step that takes away the control role after `controller remove`. Since 0.4.0 runbook-test.sh also checks `network config check/apply/show`, that a stale file is refused, and policy tests via `network config get policy.test.0.expect`.

The guide has a "Configuration" section under "Before you start" (webjetd.toml vs the network configuration with network/local scope). Runbook 1 step 7 applies one `network.toml` (show → edit → check → apply); runbook 2 edits the policy in it; runbook 3 sets relay capacity with `webjetctl local config --node relay-07 set limits.value.relay_capacity_mbps …` and adds seeds with `network config set seeds.N …`; runbook 7 uses `network config edit/set transport.camouflage.*`; runbook 11 notes that 0.4.0 has no StateVersion gate (upgrade controllers before the first network config apply, all nodes before the first node config; move `[transport]`/`[limits]` out of webjetd.toml first).

Facts the guide relies on: a node listens only where `[listen]` says (no default listener); the first controller enrolls its own node through its running agent — runbook 1: `webjetctl local init --genesis` makes it run the controller role, its node is enrolled with `--roles data,relay,control`, and step 6 is `webjetctl network controller certify ctl-01` (admin-signed; root-signing via cert-request is the alternative); runbook 4: `webjetctl network node update ctl-06 --roles data,relay,control` (the agent starts the controller without a restart), then `controller certify`, then add-learner and promote; runbook 8: revoking an admin or giving an admin a new key voids the controller certs that admin signed — re-certify them with another admin first; runbook 10: after `controller remove`, take away the control role (it is refused while the node is a Raft member); listening on 443 as user `webjet` needs CAP_NET_BIND_SERVICE in the unit (after v0.2.2); a revoked node disappears from `webjetctl network node list` rather than showing `VALID false`; `webjetctl root node revoke` takes the node id (hex) from `webjetctl network node show`; `webjetctl root admin revoke` and `root account revoke` take the account's `.pub`; `webjetd signer` has no ready-made service file; `force-new-cluster` and snapshot export/restore are not implemented (runbook 12 says so).

runbook-test.sh checks that ctl-01 shows `data,relay,control` after certify and that ctl-02 shows `control(uncertified)` before it is certified.
