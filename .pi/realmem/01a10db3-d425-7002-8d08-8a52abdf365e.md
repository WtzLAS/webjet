Changed (after 0.6.1) so that new or better relays get used and the graph stays current:
- crates/webjetd/src/agent.rs `connections`: edge nodes keep HOME_RELAYS=3. Every EXPLORE_EVERY=60 s they dial every relay in parallel (`dial_tracked`, shared `Backoff`). After EXPLORE_MEASURE=15 s, `prune_home_relays` keeps the best 3 by `best_hop().cost()` (`pick_home`, current home relays count 10% cheaper) and retires hops to the others, unless a local circuit's `next` is that relay. Between rounds, a missing home relay is refilled from the lowest `link_history` cost. Core nodes dial everything as before. Unit test `agent::tests::home_relays_keep_the_cheapest_with_hysteresis`.
- crates/webjetd/src/paths.rs `run`: every TRIAL_EVERY=30 s an active session opens a trial circuit on the best candidate not tried in TRIAL_FORGET=300 s. When there are more than MAX_CIRCUITS=2 source circuits, the worst one with at least MEASURED_PROBES=3 probe samples (never the primary) is closed.
- crates/webjetd/src/gossip.rs: LSA_REFRESH 1 min / LIFETIME 5 min (was 5/15); ATTACH_REFRESH 10 s / LIFETIME 30 s (was 20/60); publish_lsa checked every 2 s; triggered when RTT changes more than LSA_CHANGE=10% (was 20%).
- The `topology` control command calls `gossip::watch_all`. On an edge node this sends Lookup + subscribe (ttl 180 s) for every non-relay node to its core hops, renewed every 60 s for 120 s after the last request, so webjet-app sees every node's attachments and delays. on_lookup never shortens an existing subscription.
- webjet-app refreshes every 2 s (was 5 s) and skips a refresh while one is in flight (`refreshing`). Traffic::KEEP=151.
Docs were updated in webjet-architecture.md §6.7, §10.6, §10.6.1, §11.3, §11.4 step 4, §17.5, §18.3. scripts/local-net.sh has only one relay, so exploration and the watch weren't exercised end to end there.
