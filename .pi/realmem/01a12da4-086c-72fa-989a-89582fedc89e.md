Two related areas:

## Tree-side NAT traversal settings (landed 2026-10; docs say "from 0.13.0"; punch=lan added after v0.13.0, docs "from 0.13.1", uncommitted at first)
Tree-side NAT traversal settings, separate from webjetd.toml `[nat]` (interfaces/cidrs/port_mapping per machine).
- Schema webjet.fbs: `NatSettings {punch, predict, port_mapping, host_candidates: bool = null, punch_lan: bool = null}`, `NatOverride {select, settings}`; appended `TransportConfig.nat`, `TransportConfig.nat_overrides`, `NodeConfig.nat`.
- Resolution `View::nat(node) -> store::NatPolicy` (webjet-core store.rs; all built-in true), per key: node config → first matching override that sets the key → network `[nat]` → true. `validate::transport` checks override selectors (≤64); `validate::nat_unset`; statemachine `set_node_config` treats an all-unset nat as empty (clears the leaf).
- TOML (webjet-tools config.rs): `NatSection` top-level `[nat]` + `[[nat.override]] select=[…]` (network only; node scope rejects `nat.override`); `show` doesn't write it when unset, it prints a "# [nat] built-in values in force" comment; `effective` reads control-call `effective.nat`.
- Punch levels: `[nat] punch` takes true / false / "lan" (TOML `PunchFile`, custom serde; `local config set nat.punch lan` works via parse_value → string). Wire encoding: `punch_lan: bool = null` appended; "lan" = `punch=false` + `punch_lan=true` (0.13.0 nodes read it as off). punch_lan alone sets nothing (`validate::nat_unset` ignores it; node config cleared).
- webjet-core store.rs: `enum Punch {Off, Lan, On}` (derive Ord, narrowest first; `pair()` = min; Serialize as false/"lan"/true). `NatPolicy.punch: Punch`; `View::nat` takes the first layer that sets `punch` and reads punch_lan from the same table. `NatPolicy::maps_ports()` = port_mapping && punch != Lan; `publishes_reflexive()` = punch != Lan.
- Daemon: `Node::nat_policy: tokio::sync::watch::Sender<NatPolicy>`; `nat::refresh(n)` at agent start and on HeadChanged in agent.rs (republishes EndpointRecord on change). nat.rs `run_port_mapping` watches nat_policy and waits on `NatPolicy::maps_ports` (releases mapping when turned off; webjetd.toml port_mapping=false still wins).
- Output: `local status` `nat_policy`, `local sessions` `punch.policy`, `node_config` effective `nat`.
- Tests: statemachine `nat_settings_network_overrides_and_node` (lan part), config `nat_section` (lan part), nat `lan_addresses`, punch `lan_only_punching_keeps_outside_addresses_out`. Live: local-net node-02 with punch=lan publishes only its 127.0.0.1 public listen addrs; node-03's topology doesn't show node-02's endpoints (no subscription) — check from ctl-01.
- Known limitation: a LAN using only global IPv6 or CGNAT space (user's Mac: 2001:da8:… and 100.81.100.53) gets no LAN direct paths under "lan".
- Docs: configuration.md "NAT traversal (`[nat]`)" (anchor `#nat-traversal-nat`), node-scope table, precedence; architecture §11.7 "Turning parts of it off".

## punch.rs @ 0.12.2 (tag re-created on c54ad20): sym/sym hole punching, rejected dials; supersedes v0.7.0 punch details
Hole punching between two symmetric NATs and failed-dial rejection: landed in punch.rs at 0b29802 and shipped in v0.12.2 (annotated tag on c54ad20, pushed to Forgejo; release workflow publishes from the tag).
- `crates/webjetd/src/punch.rs`: `pair_punch(n, peer)`; `should_try` needs punch != Off (only "no direct UDP hop yet" + KcpFecTls priority != 0 on both sides; NAT types no longer matter — sym/sym is punched); `should_predict` needs punch == On (peer symmetric, whatever ours is; both-side prediction). Retry schedule unchanged (15 s doubling to 5 min, immediately on RecordsChanged/HopDown).
- `Attempt.rejected: Vec<SocketAddr>`: `reject()` runs when the dial to a validated (PONG) address fails (e.g. another webjet node at the same private IP on our LAN — two LANs sharing 192.168.1.0/24; "wrong-host rejection"). Ignores stale dials (`validated != Some(addr)`), drops the address from `theirs`, and within WINDOW (6 s since `started`) resets validated/dialing so the next PONG is nominated; after the window calls `finish` with failure. Rejected addresses are ignored by on_check (ping & pong). Offers drop candidates equal to our own `my_candidates`. `punch::status` JSON shows `rejected`.
- LAN filtering: `Attempt.lan`; `my_candidates(n, lan)` keeps only `nat::is_private` addresses (RFC1918, ULA, link-local; CGNAT 100.64/10 and global IPv6 are NOT private) and no mapping; received offers and peer-reflexive checks filtered by `nat::is_lan` (private or on the subnet of a non-tunnel, non-excluded interface; `Iface.prefix` added). transport.rs: no REFLEXIVE addrs when !publishes_reflexive; `host_ips` keeps only private ones under Lan.
- Docs: architecture §11.7 (port prediction, "Symmetric NAT on both sides", "Wrong answers" bullets); removed "Port prediction for symmetric NAT" from rejected alternatives. webjet-app model.rs nat_text for symmetric changed; 7944ccf made app text fields selectable.
- Test pitfall: on the user's Mac, 192.168.1.x routes via utun6 (VPN), so `nat::dialable` rejects it in unit tests; use documentation addresses 203.0.113.x / 198.51.100.x for punch test candidates.
- Release pattern (same as 0.12.1): bump Cargo.toml workspace version, `cargo update -w`, replace vX.Y.Z in README.md, docs/webjet-operations-guide.md, scripts/install.sh, scripts/install.ps1, and append a "0.12.x needs no order: …" sentence to the ops guide's "Releases without a StateVersion step" paragraph (before "Before upgrading a node, move any `[transport]`…").
