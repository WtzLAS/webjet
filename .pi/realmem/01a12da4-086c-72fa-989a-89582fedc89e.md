Added 2026-10 (uncommitted at first; docs say "from 0.13.0"). Tree-side NAT traversal settings, separate from webjetd.toml `[nat]` (interfaces/cidrs/port_mapping per machine).

- Schema webjet.fbs: `NatSettings {punch, predict, port_mapping, host_candidates: bool = null}`, `NatOverride {select, settings}`; appended `TransportConfig.nat`, `TransportConfig.nat_overrides`, `NodeConfig.nat`.
- Resolution `View::nat(node) -> store::NatPolicy` (webjet-core store.rs; all built-in true), per key: node config → first matching override that sets the key → network `[nat]` → true. `validate::transport` checks override selectors (≤64); `validate::nat_unset`; statemachine `set_node_config` treats an all-unset nat as empty (clears the leaf).
- TOML (webjet-tools config.rs): `NatSection` top-level `[nat]` + `[[nat.override]] select=[…]` (network only; node scope rejects `nat.override`); `show` doesn't write it when unset, it prints a "# [nat] built-in values in force" comment; `effective` reads control-call `effective.nat`.
- Daemon: `Node::nat_policy: tokio::sync::watch::Sender<NatPolicy>`; `nat::refresh(n)` at agent start and on HeadChanged in agent.rs (republishes EndpointRecord on change). `punch::should_try`/`should_predict` require both own and peer's (`view.nat(peer)`) punch/predict → either side off = no punching for the pair. `nat::run_port_mapping` watches nat_policy (`keep_mapping` in a select; releases mapping when turned off; webjetd.toml port_mapping=false still wins). `transport::host_ips(n)` gates HOST candidates in `my_addrs`.
- Output: `local status` `nat_policy`, `local sessions` `punch.policy`, `node_config` effective `nat`.
- Tests: statemachine `nat_settings_network_overrides_and_node`, config `nat_section`, punch `nat_settings_stop_punching_from_both_sides`. Verified live with scripts/local-net.sh (node-02 HOST endpoints vanish/return with `local config --node node-02 set/unset nat.host_candidates`). Note: in local-net, node-03's topology doesn't show node-02's endpoints (no subscription) — check from ctl-01.
- Docs: configuration.md "NAT traversal (`[nat]`)" (anchor `#nat-traversal-nat`), node-scope table, precedence; architecture §11.7 "Turning parts of it off".
