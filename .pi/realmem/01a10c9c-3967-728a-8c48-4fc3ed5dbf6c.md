Compression was added after 0.5.1 (architecture §9.8, the decision is in a separate memory).
- Pure logic lives in `crates/webjet-core/src/compress.rs`:
  - `algo` wire values: 0 unset, 1 off, 2 zstd, 3 lz4.
  - `Settings::resolve(node, network)` (node, then network, then built-in control=zstd / data=off; unknown values count as off), plus `check`.
  - `zstd_compress`/`zstd_decompress(cap)`: level 3, under 256 B not compressed, thread-local contexts, the frame must declare its size and that size must be at most cap.
  - `lz4_compress`/`lz4_decompress`: `len[2] || block`, under 128 B not compressed, must save at least 16 B.
  - `incompressible` (ports 443/853/22, ESP) and the per-flow `Backoff` (3 misses, then skip 32 doubling to 1024).
- Schema in webjet.fbs: `CompressionConfig {control, data: ubyte}` is appended to `TransportConfig.compression` and `NodeConfig.compression`; `CompressionMetrics` is appended to `MetricReport.compression`.
- View/validation: `View::compression(node)` in store.rs; `validate::compression`. In statemachine `set_node_config`, a compression with both values unset counts as empty.
- New wire types:
  - hop record `rec::CONTROL_ZSTD = 4` (webjet-net hop.rs);
  - e2e `ftype::DATA_LZ4 = 10`, `PROXY_LZ4 = 11`, `RPC_ZSTD = 12` (frames.rs).
  - They are sent only when this node has the plane on AND the peer's EndpointRecord features contain `zstd`/`lz4`. A node advertises only the planes it has on (`gossip::features`). Receivers always accept compressed types.
- Daemon: `crates/webjetd/src/compression.rs`.
  - Settings are cached in atomics in `n.metrics.compression`. `refresh()` runs at agent start and on HeadChanged in agent.rs `connections` and republishes the EndpointRecord when the settings change.
  - `control_record` is applied in the hop writer (node.rs) and decoded in the reader. RPC compression is in rpc.rs `encode` → `rpc_frame`.
  - Never compressed: `secret_rpc` = PskInfo, CamouflageSecret, RaftRpc.
  - Data plane: in e2e.rs `send` (`lz4_to`, which caches the peer's feature for 5 s per session, plus `compress_packet` with `Inner.lz4_backoff`) and in `on_frame`.
- Output:
  - `local status` JSON has `compression.{control,data}` with counters.
  - Prometheus gets `webjet_compression_{messages,raw_bytes,wire_bytes,skipped,errors}`.
  - The webjet-app dashboard shows a "Compression" row.
- TOML: `[transport.compression] control/data`, at network scope and node scope (webjet-tools config.rs `CompressionFile`); `show` spells out the built-ins.
- Testing:
  - `webjetctl local ping -s <bytes>` was added (payload with a pattern, at most 1232) to send compressible traffic.
  - `LZ4=true scripts/soak-test.sh` turns data compression on, pings with 1000 B and fails on decompression errors.
  - Local-net result: ctl-01 control traffic 57.7 KB → 15 KB; 1000-byte pings 1028 → 312 B.
  - Mixed with 0.5.1 nodes it was verified to work: new → old stays uncompressed.
