v0.6.0 (tagged 6473956 after the 2026-10-06 history rewrite; old hash 058aa0e gone — look up by tag/message; identity `Wtz_LASR <wtz_lasr@outlook.com>`; docs/code changed from an earlier "0.5.2" label) introduced compression: control plane (HopControl gossip/Raft/snapshot) uses zstd (`zstd` crate/zstd-sys), always on by default; data plane (e2e DATA/PROXY) uses LZ4 (`lz4_flex`) per-packet, OFF by default/opt-in (compress-before-encrypt leaks via packet lengths, VORACLE/CRIME). Setting is network-wide in TransportConfig with per-node overrides in NodeConfig (not per policy/tag); peers advertise support for mixed-version networks; secrets (PskInfo, CamouflageSecret) never compressed; decompression has a hard size cap. Ops guide: upgrade controllers first for compression and for `[[proxy]]` rules.

Implementation (architecture §9.8):
- `crates/webjet-core/src/compress.rs`: algo wire values 0 unset / 1 off / 2 zstd / 3 lz4; `Settings::resolve(node, network)` (node → network → built-in control=zstd/data=off, unknown = off) + `check`; `zstd_compress`/`zstd_decompress(cap)` level 3, <256 B uncompressed, thread-local contexts, frame must declare size ≤ cap; `lz4_compress`/`lz4_decompress` format `len[2]||block`, <128 B uncompressed, must save ≥16 B; `incompressible` (ports 443/853/22, ESP); per-flow `Backoff` (3 misses, then skip 32 doubling to 1024).
- Schema webjet.fbs: `CompressionConfig {control,data: ubyte}` in `TransportConfig.compression` and `NodeConfig.compression`; `CompressionMetrics` in `MetricReport.compression`.
- View/validation: `View::compression(node)` in store.rs; `validate::compression`; in statemachine `set_node_config`, both-unset counts as empty.
- Wire types: hop record `rec::CONTROL_ZSTD = 4` (webjet-net hop.rs); e2e `ftype::DATA_LZ4 = 10`, `PROXY_LZ4 = 11`, `RPC_ZSTD = 12` (frames.rs). Sent only if the node's plane is on AND peer's EndpointRecord features contain `zstd`/`lz4`; a node advertises only enabled planes (`gossip::features`); receivers always accept compressed types.
- Daemon `crates/webjetd/src/compression.rs`: settings cached in atomics in `n.metrics.compression`; `refresh()` at agent start and on HeadChanged in agent.rs `connections`, republishes EndpointRecord on change. `control_record` applied in hop writer (node.rs), decoded in reader; RPC compression in rpc.rs `encode` → `rpc_frame`; `secret_rpc` (PskInfo, CamouflageSecret, RaftRpc) never compressed. Data plane: e2e.rs `send` (`lz4_to` caches peer feature 5 s per session; `compress_packet` with `Inner.lz4_backoff`) and `on_frame`.
- Output: `local status` JSON `compression.{control,data}` counters; Prometheus `webjet_compression_{messages,raw_bytes,wire_bytes,skipped,errors}`; webjet-app dashboard "Compression" row.
- TOML: `[transport.compression] control/data` at network and node scope (webjet-tools config.rs `CompressionFile`); `show` spells out built-ins.
- Testing: `webjetctl local ping -s <bytes>` (patterned payload, max 1232); `LZ4=true scripts/soak-test.sh` enables data compression, pings 1000 B, fails on decompression errors. Local-net: ctl-01 control 57.7 KB → 15 KB; 1000-B pings 1028 → 312 B. Mixed with 0.5.1 verified: new → old stays uncompressed.
