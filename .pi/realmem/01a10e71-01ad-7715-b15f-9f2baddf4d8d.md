`crates/webjet-app/src/graph.rs` `layout(items: &[Item], edges, area_px)` replaced the old Fruchterman–Reingold layout (2026-10). Design:
- Lays out each connected component on its own (`Part`). Uses stress majorization on hop distances × ideal edge length from several starts (rings around the top-3 degree nodes plus scattered starts from a deterministic xorshift `Rng`), each followed by `turn_and_stretch` to fit the area's aspect ratio.
- `Cost` adds up crossings (`crossing` = CROSSING_SMALL 40 for ≤16 nodes, else 4), edges through another node's label box (HIT 20), overlapping padded boxes (OVERLAP 10), near-parallel edges at a node (ANGLE, MIN_ANGLE 20°) and stress. `of(pos, vs)` is incremental.
- Components with ≤16 nodes (ANNEAL_MAX) are simulated-annealed from the 3 cheapest starts. Larger ones get the `improve` local search (swaps + moves near neighbours) under SEARCH_BUDGET.
- Then `separate` pushes boxes apart, `pack` arranges components on shelves, and the picture is fit to the area. If it doesn't fit, `Part::shrink(kx, ky)` refines at the smaller scale, because labels keep their pixel size.
- Warm start / no-move refresh (2026, after user complaint about graphs jumping on every data change): `Graph::keep(previous)` ALWAYS keeps every existing vertex's x/y (fractions) and `previous.area`, and places only new vertices with `place()`: rings (PLACE_STEP 20 px) around the mean of placed neighbours (area centre if none), first ring with a free box (PLACE_GAP 10 px), cheapest by link length + PLACE_CROSSING 80 × (crossings + links through labels) − room; inside the area preferred. Returns false only when no old vertex survives → caller does a full `lay_out(None)`. (`same_shape` removed; the old rule "same shape and area within 10 %" is gone.) Stress majorization no longer runs on warm starts.
- `WebjetApp::loaded` (ui/mod.rs): full layout only for the first picture, when nothing of the old picture survives, or ONCE when the graph was made for the unmeasured `DEFAULT_AREA` and the real area is now known (no pinned nodes, `!laying_out`). `start_layout` runs on `cx.background_executor()` via `layout_job`/`layout_seq` and applies the result with `now.keep(Some(&laid_out))` (a refresh may have landed meanwhile); the `laying_out` flag prevents restarting the job on each 2 s refresh. First picture is laid out synchronously.
- Re-layout button is always enabled (was only with moved nodes).
- Label box sizes come from `vertex_box(label, infra)` with CHAR_W 7.8 px. Measured text_xs ≈ 7.3 px/char; the `graph_labels_do_not_overlap` UI test checks drawn width ≤ layout width.
- Selection focus: `Graph::focus(selected, circuit_path)` returns vertices/edges in focus; nodes.rs draws two layers (edges canvas, delay labels, vertices): rest dimmed (links 0.35, labels/nodes 0.3), focus on top with solid label backgrounds.
- Debug pictures: `WEBJET_LAYOUT_SVG=/tmp/dir cargo test --release -p webjet-app --lib graph::tests`, then `qlmanage -t -s 1000 -o . file.svg` for a PNG (no rsvg/magick on this Mac).
- Timing: ~200 ms release / ~2.5 s debug for the 9-node network; timing assertions in tests depend on `cfg!(debug_assertions)`.
- Tests: graph::tests `a_refresh_never_moves_a_node`, `new_nodes_go_next_to_their_neighbors_into_free_room`; ui::tests `refreshes_do_not_move_the_nodes`. docs/app.md Nodes section documents this.
