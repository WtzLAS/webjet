`crates/webjetd/src/controller/raft.rs` `Storage::load_log` (Disk): log.bin is length-prefixed records appended with `append` (O_APPEND + sync_data). A crash mid-append leaves a torn final record. load_log used to only skip it ("truncated tail ignored"), so entries appended after the restart landed *behind* the torn bytes and the next restart never read them: acknowledged Raft entries were silently lost. Now load_log `set_len`s the file to the last complete record (warns "raft log: torn tail of N bytes dropped"). Covered by `disk_storage_roundtrip` in raft_tests.rs (append after a torn tail, then reload → 5 entries).
