Since the 2026-10 code-review round A: `Node::persist_store` (crates/webjetd/src/node.rs) no longer holds the store read guard during the disk write. `store_copy()` takes `state::store_file(&store)` plus a sequence number (`store_copies`, incremented under the read guard so a later number never holds an older state); `save_store_copy(seq, f)` runs inside `crate::tasks::blocking` (block_in_place on the multi-thread runtime; moved there from controller/mod.rs, shared by controller and node) and holds the `store_saved` mutex while writing, skipping a copy older than the one already on disk. `store.json` is now compact JSON (`state::save_store_file`, serde_json::to_vec); `load_json` reads both forms. `persist_links` merges live hop histories into `link_history` under one lock and writes via `blocking`. Test: `node::hop_tests::persist_store_keeps_the_newest_copy`.
