After v0.6.0 all direct deps were moved to latest majors: rand 0.10, rand_core 0.10, ed25519-dalek 3, chacha20poly1305 0.11, aes-gcm 0.11, argon2 0.6, base64 0.23, toml 1, hickory-proto 0.26, dirs 7, if-addrs 0.15, windows-sys 0.61, sha2 0.11, zip 9 (webjetup; was 8, no code changes needed, tests pass).

API mapping used:
- `OsRng.fill_bytes` → `rand::rand_core::UnwrapErr(rand::rngs::SysRng).fill_bytes` (needs `rand::Rng` in scope).
- `thread_rng()` → `rand::rng()`; `gen_range` → `random_range`, `gen_bool` → `random_bool` (trait `RngExt`).
- `StdRng::from_entropy()` → `rand::make_rng()`.
- `SliceRandom::choose_multiple` → `IndexedRandom::sample`.
- `rand::random::<usize>()` gone; use `rand::random_range(0..n)`.
- aead 0.6: `AeadInPlace` deprecated; use `AeadInOut::encrypt_inout_detached(nonce, aad, buf.as_mut_slice().into())` / `decrypt_inout_detached(.., tag.try_into().ok()?)`. `Key::from(arr)`, `Nonce::from(arr)`, `XNonce::try_from(slice)` replace `from_slice`.
- sha2 0.11 `Sha256` no `io::Write`; feed with `update` in a read loop.
- hickory-proto 0.26 `Message` has public fields `metadata` (id, op_code, recursion_desired/available, response_code, authentic_data), `queries`, `answers`, `additionals`; build replies with `Message::response(id, op_code)`; `Record.data` is `RData`, not `Option`. `crates/webjetd/src/dns.rs` has pure helpers `response_to` and `fix_forwarded`, tested with raw wire bytes.

Wire compat verified with an example built against old and new commits: Ed25519 signatures, e2e frames, Argon2 key-file seal, UDP gate interoperate.

After the 2026-10 `cargo update`, the only crate behind newest is generic-array 0.14.7, pinned `=0.14.7` by crypto-common 0.1.7 (via gpui → oo7 → cipher); no newer majors for direct workspace deps besides that. In vendor/gpui/Cargo.toml and vendor/gpui_media/Cargo.toml the exact pins were relaxed, each with a `Webjet:` comment: `core-foundation "=0.10.0"` → `"0.10"` (netconfig-rs 0.1.6 via tun-rs/webjetd needs 0.10.1; also pulled in netlink-packet-route 0.25) and `taffy "=0.9.0"` → `"0.9"`. `cocoa =0.26.0` and `cocoa-foundation =0.2.0` deliberately stay pinned: cocoa 0.26.1 deprecates its whole API (objc2 migration), flooding the macOS gpui build with deprecation warnings. Redo these relaxations when updating vendored gpui (listed in vendor/README.md).

Side effect: the RNG change shifted Raft sim timing; `prevote_keeps_a_partitioned_follower_from_disrupting` now runs 1 s with no new proposals before comparing state-machine lengths.
