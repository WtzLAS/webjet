Since v0.2.0 (workspace version 0.2.0), Webjet hosts install with `crates/webjetup` (clap CLI; ureq with rustls/aws-lc provider + webpki roots; tar/flate2/zip) instead of `scripts/upgrade.sh`/`upgrade.ps1` (deleted). Commands: `install [VERSION]` (alias `upgrade`; `--enroll wj1:…`, `--from <dir|archive>`, `--force`, `--no-start`), `enroll <STRING|->`, `status`, `list`, `remove` (alias `uninstall`; keeps /var/lib/webjet identity and webjetup), `nuke` (also state, config, Keychain items service `net.webjet.identity`, /etc/resolver `# webjet` files, `resolvectl revert webjet0`, user `webjet`, webjetup itself — not account keys in $HOME). Global `--dry-run`, `--repo`/`WEBJETUP_REPO` (default https://forgejo.wolf109909.top/webj8/webjet, compile-time overridable via env WEBJETUP_REPO). remove/nuke need `--yes` without a TTY. Installs into /usr/local/bin (creates it — fresh Apple Silicon Macs lack it), Windows %ProgramFiles%\Webjet + machine PATH + icacls on %ProgramData%\Webjet; webjetup copies itself next to the programs. Linux unit adds `SupplementaryGroups=tss` when group tss exists (TPM). Checks the release exists via API `releases/tags/<tag>` first (Forgejo's download 404 sometimes surfaces as "connection reset" through the local proxy), verifies `.sha256`, runs the staged `webjetd --version` before stopping the old agent. `scripts/install.sh` (POSIX sh, root) picks `webjetup-<tag>-<target>` (latest via API unless WEBJET_VERSION), verifies sha256, runs `webjetup --repo $REPO install "$@"`. Release assets add `webjetup-<tag>-<target>[.exe]` + `install.sh`, each with `.sha256`. Forgejo has no `releases/latest/download/<file>` URL (404), so docs name a tag. Tests: `docker/webjetup-test.sh` (pre-release, local fake forge + controller + systemd-booting container: install.sh --enroll, ping, reinstall, remove, nuke); `docker/release-test.sh <tag>` (published release, via install.sh). Container images lack `ps`; use `systemctl show -p MainPID` + `stat -c %U /proc/<pid>`. v0.2.1 fix (v0.2.0's webjetup has the bug; install.sh from any release fetches the latest webjetup): the workspace builds rustls with `prefer-post-quantum` (overlay requires X25519MLKEM768); ureq's webjetup HTTPS client then sent a large X25519MLKEM768 key share first and forgejo.wolf109909.top (or a middlebox) reset ~20–30% of handshakes ("io: Connection reset by peer (os error 54)"), directly and via the local proxy — curl and a harness without the feature never failed. Fix in `crates/webjetup/src/release.rs`: `provider.kx_groups = classic_kx_groups()` (X25519, P-256, P-384) for downloads (files are SHA-256-checked anyway), plus `retry()` with Failure::Retry/Final (4 attempts, 1/2/4 s; 404 and other 4xx final). Also: Rust CLIs ignore SIGPIPE → `println!` panics with "failed printing to stdout: Broken pipe" under `| grep -q`; webjetup restores SIG_DFL at start on Unix.
