Since v0.2.0 hosts install with `crates/webjetup` (clap; ureq + rustls with the aws-lc provider and webpki roots; tar/flate2/zip); `scripts/upgrade.sh` and `upgrade.ps1` were deleted. Commands: `install [VERSION]` (alias `upgrade`; `--enroll wj1:…`, `--from <dir|archive>`, `--force`, `--no-start`), `enroll <STRING|->`, `status`, `list`, `remove` (alias `uninstall`; keeps the identity in /var/lib/webjet and webjetup itself), `nuke` (also state, config, Keychain items of service `net.webjet.identity`, `/etc/resolver` files marked `# webjet`, `resolvectl revert webjet0`, the `webjet` user and webjetup; not account keys in home directories). Global `--dry-run` and `--repo`/WEBJETUP_REPO (default https://forgejo.wolf109909.top/webj8/webjet). remove/nuke need `--yes` without a TTY.

Install layout: /usr/local/bin (created if missing — fresh Apple Silicon Macs lack it); Windows %ProgramFiles%\Webjet, machine PATH, icacls on %ProgramData%\Webjet. Linux systemd unit: `User=webjet`, `AmbientCapabilities`/`CapabilityBoundingSet` = CAP_NET_ADMIN CAP_NET_BIND_SERVICE (the bind capability was added after v0.2.2; v0.2.2's unit can't listen below port 1024), `SupplementaryGroups=tss` when the group exists (TPM). `webjetup enroll` stops the agent, runs `webjetctl enroll` (`webjetd enroll` when the installed version is before 0.3.0, `layout::before_0_3`), fixes ownership of the state and (re)starts the service — except on a bootstrap controller (`"bootstrap": true` in node.json, written by `webjetctl init`), whose running agent performs the enrollment, so it's left running (fixed after v0.2.2). Before stopping an old agent, install runs the staged `webjetd --version`. It asks the API `releases/tags/<tag>` first for a clear "no such release" error and verifies every download's `.sha256`.

Download TLS (fixed in v0.2.1; v0.2.0's webjetup has the bug): the workspace builds rustls with `prefer-post-quantum`, so webjetup's HTTPS client sent a large X25519MLKEM768 key share first, and the release server (or something on the path) reset about 20–30% of those handshakes ("Connection reset by peer"). This was first wrongly blamed on Forgejo 404s and the local proxy. Fix in `crates/webjetup/src/release.rs`: classic key exchange groups (X25519, P-256, P-384) for downloads (files are SHA-256-checked anyway) plus `retry()` (4 attempts, 1/2/4 s; 404 and other 4xx are final). webjetup also restores SIGPIPE's default on Unix so `| grep -q` doesn't panic.

`scripts/install.sh` (POSIX sh, root) picks `webjetup-<tag>-<target>` (the latest via the API unless WEBJET_VERSION), verifies its sha256 and runs `webjetup --repo $REPO install "$@"`. Tests: `docker/webjetup-test.sh` before a release, `docker/release-test.sh <tag>` after.
