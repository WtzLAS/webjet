Remote upgrades (never on Docker installs; Linux/macOS/Windows) are delivered as a signed `UpgradeRequest` (webjet.fbs, msg `UPGRADE_REQUEST = 30`; RPCs `UpgradeNode`/`GetUpgradeStatus`/`UpgradeReply` appended to `RpcBody` in wire.fbs; new tables at file end). **Crate `crates/webjet-release`:** targets, `archive_name`/`webjetup_name`, `Version` ordering, spool dir (`/var/lib/webjet-upgrade` on Linux, `…/Webjet/upgrade` on macOS/Windows), `queue/request.json` (`QueuedRequest` = signed request + admin's root-signed AccountRecord), `trust.json` (root key, node id, repo), `status.json`, `plan()` (helper's full check), `read_untrusted`/`write_atomic`; feature `http` holds the release client (`published_sha256`, `fetch_pinned`) moved out of webjetup release.rs. **webjetd `upgrade.rs`:** `check_signed` verifies against the tree; `on_rpc` routed from `rpc.rs` on every node (controllers forward one hop); control commands `upgrade` (Signed) and `upgrade_status` (Read); `[upgrade] remote` default true in config.rs; hidden `webjetd features` prints `remote-upgrade`. **Consent:** on by default; opt out via `webjetup install --no-remote-upgrade` (no helper) or `[upgrade] remote = false` in webjetd.toml. **Executor:** webjetup `remote.rs` `setup` (runs on install/enroll) installs `webjet-upgrade.path`+`.service`, a `webjetd.service.d/remote-upgrade.conf` drop-in with `ReadWritePaths`, launchd `net.webjet.upgrade` (QueueDirectories), Windows scheduled task "Webjet upgrade"; webjetd only writes the validated request; `trust.json` pinned only on enroll or if missing. **Apply:** hidden `webjetup apply-upgrade` backs up to `<spool>/previous`, installs, replaces webjetup itself, waits up to 120 s for health check (`webjetctl --json local status` version), rolls back otherwise; downgrades refused. **Rollout:** `webjetctl network node upgrade <ver> <nodes|--tag|--all> [--batch --repo --dry-run --yes --timeout-minutes]` and `network node upgrade-status`; logic in `crates/webjet-tools/src/upgrade.rs` — learners, then voters (leader last), relays, then the rest; admin's own node last; CLI waits for EndpointRecord.software + online, stopping at first failure. **e2e:** `docker/webjetup-test.sh` step 6 builds release +1 and a "bad" +2 (old binaries); tests upgrade, rollback, downgrade skip, opt-out (~20+ min, 2-min rollback wait). **webjetup self-update exception:** only `apply-upgrade` and `scripts/install.sh` replace webjetup; ordinary install/upgrade copies the running binary. Other details unchanged: install layout /usr/local/bin, Windows %ProgramFiles%\Webjet; systemd User=webjet, CAP_NET_ADMIN CAP_NET_BIND_SERVICE, SupplementaryGroups=tss; enroll flow incl. bootstrap-controller exception; --repo/WEBJETUP_REPO default https://forgejo.wolf109909.top/webj8/webjet; release archives contain only webjetd and webjetctl; download TLS fix (classic key groups + retry) in crates/webjetup/src/release.rs; also docker/release-test.sh <tag>.
