Webjet config model (0.4.0, clean break after v0.3.0): all config is TOML in two kinds.
- `webjetd.toml` (crates/webjetd/src/config.rs) is daemon-only (listen, public, tun, dns.configure_system, gateway, key, metrics, controller, log). `[transport]`/`[limits]` were removed; `Config::check_removed` refuses to start with them, naming the `webjetctl local config set ...` replacement. `[controller] enabled` is a plain bool (default true).
- Network config lives in the signed tree: one `NetworkConfig {version, policy, dns, seeds, limits, transport}` via op `SetNetworkConfig` (admin), writing the 5 singleton leaves in one entry with the document's version; `View::network_version` = max of the 5. Version must be > current (optimistic concurrency). Old SetPolicy/SetDns/SetSeeds/SetLimits/SetTransport still apply if already in the log, but `Machine::prepare` refuses new ones (`refuse_retired`).
- Node scope: `NodeConfig {node_id, version, priorities, limits, seeds, dns_records, dns_forward}` via `SetNodeConfig` (node owner OR admin, `owner_or_admin`); leaf kind `merkle::kind::NODE_CONFIG = 9`, msg_type 26. Empty config deletes the leaf; TombstoneNode too.
- Precedence (`View::priority`, `View::limit`, `seeds_for`, `dns_records_for`, `dns_forward_for` in webjet-core store.rs): node config > network overrides (priority: first match per transport; limits: highest) > network value > built-in (`store::BUILTIN_PRIORITIES`, `validate::LIMITS`). Seeds/records/zones: node's first, then network's. For peers, `transport::priority` still prefers priorities in their EndpointRecord. `policy::selects(sels, subject)` is the shared selector matcher.
- TOML schema + show/merge/get/set/unset in crates/webjet-tools/src/config.rs (`ConfigFile`): `[policy]` with `[[policy.rule]]`/`[[policy.test]]`, `[dns]` with `[[dns.record]]`/`[[dns.forward]]`, `[[seeds]]`, `[transport.priority]`, `[[transport.override]] {select, priority}`, `[transport.camouflage]` (cert = file path or inline PEM; show prints inline PEM + `next_spki` hex so shown files re-apply), `[transport.padding]`, `[limits.value]`, `[[limits.override]] {select, value}`. `version` in the file = version it was made from; apply submits +1 and refuses a mismatch. Sections left out of a network file stay as-is (`ConfigFile::over` merges onto `network_from_tree(tree, fill=false)`). Node scope rejects policy, dns.suffix/resolver_ip, transport.override/camouflage/padding, limits.override.
- Control calls: `node_config` (webjetd control.rs) returns a node's config + effective values; `tree` returns `network_version` (plus policy wire form, resolver in force, suffix).
- The 17 limits all remain enforced via `webjet_core::validate::LIMITS` with spec §16.2 numbers (circuits 64/source, 10 setups/s per source; SNAT limits = conntrack gateway flows via `Conntrack::insert(.., gateway, ..)`, errors SnatPeerQuota/SnatGlobal count `snat_exhausted`; e2e handshakes per sec/global, handshake_queue, hop_handshakes_per_ip via `transport::HandshakeGate` (TCP) and `UdpEndpoint::per_ip_limit` (KCP); lookups_per_sec, subscriptions_per_peer, rate_ceiling from tree; transport limits re-applied on HeadChanged via `transport::apply_limits`, conntrack limits on dataplane refresh). DNS resolver default: `View::resolver_ips(pool)` = DnsConfig `resolver_ip`, else per family the highest host of the first overlay pool not held by a node (10.7.0.0/16 → 10.7.255.254; IPv6 hosts() includes all-ones); reserved by the state machine (enrollment rejected) — deterministic, all controllers must run this version. Padding: `padding::DEFAULT_LINES`/`DEFAULT_STOP`; hop writers use TransportConfig's padding scheme when set.
- Docs: docs/configuration.md (both kinds), architecture §6.18/§6.19. Upgrade note: no StateVersion gate; upgrade all controllers before first network config apply, all nodes before first node config (0.3 nodes can't decode NODE_CONFIG leaves).
