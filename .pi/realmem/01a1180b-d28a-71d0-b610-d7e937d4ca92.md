Since 0.10.3, `webjetctl network node upgrade` (crates/webjet-tools/src/bin/webjetctl/rollout.rs) runs each stage's per-node work concurrently: `send()` does UpgradeStatus → skip checks → sign → `Request::Upgrade` and returns `Sent::{Already, Skipped, Queued{from,id}}`; `together()` runs futures via `futures::stream::iter(..).buffered(PARALLEL)` (PARALLEL = 16, below webjetd's control `MAX_CONNECTIONS` = 64), keeping stage order for output. The 5 s status poll of queued nodes is also concurrent. So offline nodes cost a batch one RPC timeout (webjetd upgrade FORWARD_TIMEOUT) together, not one each. Controllers remain one per stage. webjet-tools now depends on `futures` (workspace). Ops guide 3.3 says so; "Releases without a StateVersion step": 0.10.3 needs no order.
