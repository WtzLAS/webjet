Reverse proxy feature (added after 0.5.1, Linux only for ingress and real-IP targets):
- Rules: `[[proxy]]` in node-scope config (`webjetctl local config`), wire `NodeConfig.proxy: [ProxyRule]` {name, protocol 6/17, listen_port, target [one IP | selectors], target_port, real_ip=true}. Validated by `webjet_core::proxy::rules` (also in statemachine `set_node_config`; data role required). TOML in webjet-tools config.rs `ProxyFile`.
- Ingress: iptables chain `WEBJET-PROXY` (nat PREROUTING DNAT listen ports → proxy address = overlay resolver IP; filter/mangle FORWARD accept + TCPMSS). `crates/webjetd/src/proxy.rs` `Proxy::from_client` picks target (address via `Dataplane::route`, selectors via rendezvous hash `proxy::rank`), rewrites, sends e2e frame type `ftype::PROXY = 9`.
- Target: `[proxy] accept_real_ip = true` in webjetd.toml → mangle `WEBJET-REALIP`/`WEBJET-REALIP-OUT`, connmark 0x574a0000/0xffff0000, ip rule → table 22346 default dev tun, rp_filter=2; advertises EndpointRecord feature `proxy-real-ip` (all new nodes advertise `proxy`). Otherwise ingress SNATs to its overlay IP, ports 61000–65535. Targets behind gateways are always SNAT'd; real_ip=true there gives a rule warning + `proxy_rule` alarm.
- real_ip + UDP server bound 0.0.0.0 (srcds default), fixed (2026-10): `Proxy::to_target` adds per-flow `ip rule add to <client>/32 ipproto udp sport <port> dport <client port> iif lo lookup 22346 priority 22345` (`platform::proxy_reply_route`, `REAL_IP_UDP_PRIO`) for real-IP UDP flows to the node's own addresses, added in spawn_blocking BEFORE the first packet hits tun so the reply is routed into tun with overlay source. Bookkeeping in `Proxy.reply_routes` (cap REPLY_ROUTE_CAP 1024); `sweep_reply_routes` at end of `refresh` (10 s) drops dead flows; `proxy_clear` removes all prio-22345 rules via `ip -force -batch`. Needs Linux 4.17; on failure the agent warns once. `admit` returns `(rule, real_ip)`.
- Separation: own `proxy::Table` (separate Conntrack), not counted in tun_rx/tun_tx/conntrack; control call `proxy` / `webjetctl local proxy`; `MetricReport.proxy: [ProxyMetrics]` → `webjet_proxy_*` families; webjet-app Connections tab has an "overlay flows / reverse proxy" switch (fixture node-02.json has a `proxy` key; written json indent=1, sort_keys, ensure_ascii).
- UDP fragments (2026-10, gmod/srcds): datagrams > tun MTU (1280) arrive fragmented; only first has ports. `webjet_core::proxy::Table` `frags: HashMap<FragKey{from: Option<peer>, proto, src, dst, id}, (FragRoute, Instant)>` (FRAG_TIMEOUT 30 s, FRAG_CAP 8192); `add_frag` on first fragment at 4 points (from_client, from_peer ingress reply, to_target, from_local); `later_fragment()` in webjetd proxy.rs forwards later fragments (addresses-only rewrite); `is_capture` accepts any Fragment::Later to the proxy address; `packet::rewrite` adjusts first-fragment L4 checksum incrementally (`l4_sum_fields`/`adjust_l4_checksum`). Docs: architecture §11.11 "Fragments." paragraph.
- Tested by docker/e2e.sh: real IP to node-b (asserts `ip rule show priority 22345` contains `sport 27015` on node-b), UDP by selector with SNAT, two rules to a LAN host behind gw, removal clears capture, 1400-byte UDP fragment check. E2E pitfall: first UDP datagram > tun MTU is dropped "fragmentation needed" and netcat-openbsd quits on EMSGSIZE — send a priming datagram first. In test containers config is `$WEBJET_CONFIG` (/run/webjet/webjetd.toml), not /etc/webjet; no tcpdump/conntrack preinstalled but internet works (`apt-get install tcpdump conntrack`). netcat-openbsd UDP listen needs `-p PORT` with `-s ADDR`.

Phase 2 fixes (commits cf95d4f..3dfac66):
- `packet::Parsed.frag_id` (IPv4 Identification / IPv6 frag header id; 0 when whole). `Conntrack` keeps `frags: HashMap<FragKey{peer,proto,src,dst,id}, Instant>` (FRAG_TIMEOUT 30 s, FRAG_CAP 16384): set when a First fragment is inserted or Tracked; Later fragments matching are Tracked; otherwise UDP/other Later → New, TCP/ICMP → Invalid; `initial_state` returns None for Later (never inserted). Cleared on drop_peer, on reevaluate dropping flows, pruned in expire.
- webjetd node.rs `DialSlot` RAII guard for `Node::dialing` (dial_node runs under 12 s timeout); `register_hop` duplicate check + insert under one `hops` lock (loops after PeerLost replacement).
- dataplane.rs: `Routes {installed, failing}`; `platform::add_route/del_route` return bool; failed adds retried each refresh. `Dataplane.system: Mutex<bool>` held by refresh and shutdown for their whole run; refresh no-ops after shutdown.
- webjet-net fec.rs Decoder keeps groups by `newest.wrapping_sub(g) < WINDOW(64)`.
- webjet-core proxy.rs `Table::forget` only removes by_client/by_flow mapping still pointing at the forgotten key.
- webjet-tools `config::edit_network` (set/unset at network scope) keeps emptied sections as empty so `over()` doesn't merge old values back.
- webjetctl: enrollment ticket built before submit (enroll/rekey); `expires_at()` checked; account rekey uses the account's real name.
