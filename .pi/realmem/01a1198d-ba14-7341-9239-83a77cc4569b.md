`docker/mdns-test.sh` builds `webjet:mdns`, which is `webjet:test` plus avahi-daemon, avahi-utils, libnss-mdns and dbus, built inline from a heredoc. It runs ctl-01 and h-1..3 (`tag:home`) plus o-1 (`tag:office`) with both pools, 10.7.0.0/16 and fd00:7::/64 (`--overlay-pool` twice, `--ip` twice); the containers need `--sysctl net.ipv6.conf.all.disable_ipv6=0`. It takes ~3 min and passed on 2026-10-08.

Pitfalls:
- Avahi needs `allow-point-to-point=yes` and `allow-interfaces=webjet0` on tun interfaces, and has to be started with `dbus-daemon --system --fork` and then `avahi-daemon -D --no-rlimits`.
- `avahi-browse -p` escapes a space as `\032`.
- Debian's `mdns4_minimal` in nsswitch resolves IPv4 only (getent ahostsv6 gives ::ffff:v4); use `avahi-resolve -6`.
- `avahi-resolve` exits 0 even on "Timeout reached", so check its output.

Known tradeoff: echo detection (same kind and payload within 1 s) can drop a host's mDNS query that is byte-identical to a peer's query just delivered. That is harmless; it matches RFC 6762 §7.3 duplicate question suppression.
