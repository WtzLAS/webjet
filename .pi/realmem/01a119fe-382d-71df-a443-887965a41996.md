FreeBSD (x86_64-unknown-freebsd) cross-builds from the Mac go through `scripts/freebsd-cargo.sh <cargo args>`; it first runs `scripts/freebsd-sysroot.sh`, which downloads FreeBSD 14.4-RELEASE base.txz (SHA-256 pinned) into `$WEBJET_FREEBSD_SYSROOT` (default `~/.cache/freebsd-sysroot/x86_64`, keeps `./lib ./usr/include ./usr/lib`), then sets CC/CXX/AR, sysroot flags, clang linker with `-fuse-ld=lld`, and `CARGO_BUILD_TARGET`; uses Homebrew llvm/lld on Mac or `$WEBJET_FREEBSD_LLVM` elsewhere. Boring-sys (default anytls feature) needs `CXXFLAGS_x86_64_unknown_freebsd="--sysroot=$SR -nostdinc++ -isystem $SR/usr/include/c++/v1"` (Homebrew clang headers fail with 'vendor availability markup'; CMake then 'Failed to determine the source files for the regular expression backend') and `BINDGEN_EXTRA_CLANG_ARGS_x86_64_unknown_freebsd=--sysroot=$SR` (else bindgen: 'stdlib.h not found'). Binaries need libc++.so.1 and libcxxrt (in FreeBSD base); highest symbol version FBSD_1.7 => FreeBSD 14.0+/OPNsense 24.7+; `scripts/release.sh build_freebsd` dies if a binary needs > `FREEBSD_MAX_SYMVER=FBSD_1.7`. CI: builder image `webjet-builder:3` (freebsd rustup target, `/opt/freebsd-sysroot`, `ENV WEBJET_FREEBSD_SYSROOT`; build from repo root: `docker build --platform linux/amd64 -f ci/builder.Dockerfile -t …:3 .`; on Mac add `--build-arg http(s)_proxy=http://host.docker.internal:7890` or DNS for index.crates.io fails); `ci.yml` has 'clippy (FreeBSD)' step; `release.yml` targets include x86_64-unknown-freebsd; `scripts/release.sh` ALL includes it via `build_freebsd`. First release with FreeBSD artifacts: the one after 0.10.3. No FreeBSD VM/qemu on the Mac, so runtime untested.
