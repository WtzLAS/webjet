User decision (after 0.5.0): the webjetd control channel must be usable without root by `webjetctl` and `webjet-app`. Implementation in `crates/webjetd/src/ipc.rs`: `Listener::bind(path, Access)`. `Access::Everyone` (control channel, `control.rs serve`): Unix socket mode 0666, and when the socket is in the default dir (`/var/run/webjet`) the agent adds o+x to that dir at start, because older webjetup systemd units create it with RuntimeDirectoryMode=0750 (new units use 0751). On Windows the pipe uses SDDL `D:P(A;;GA;;;SY)(A;;GA;;;BA)(A;;0x12008b;;;WD)`: everyone gets FILE_GENERIC_READ|FILE_WRITE_DATA but not FILE_APPEND_DATA (= FILE_CREATE_PIPE_INSTANCE). So `ipc::connect` opens the pipe with std OpenOptions access_mode GENERIC_READ|FILE_WRITE_DATA + FILE_FLAG_OVERLAPPED + SECURITY_IDENTIFICATION and wraps it with `NamedPipeClient::from_raw_handle`. tokio's ClientOptions asks for GENERIC_WRITE and would be denied. `Access::Private` (0600; SYSTEM+Administrators) is kept for `webjetd signer`'s socket. Rationale: every state change through the channel is signed (account/root/emergency), so the socket grants no rights; the trade-off accepted is that any local user can read the network map and conntrack. Docs updated: docs/configuration.md control_socket, docs/app.md, the ops guide's "Running webjetctl" section (sudo only for `local init`/`local enroll`), architecture §19.5, README platform table. `docker/webjetup-test.sh` checks that an unprivileged user (`su wjuser -c "webjetctl local status"`) works.
