Since the post-0.6.1 rework:
- `crates/webjetd/src/nat.rs`: tunnel-interface detection (POINTOPOINT flag + name prefixes wg/tun/utun/tap/tailscale/zt/ppp/ipsec/nordlynx…; overlay `webjet*` always excluded), `candidate_ips` (public first, max 8; replaces old `platform::local_ips` which sorted+truncated to 4 and dropped public IPs), `via_tunnel(dst)` (egress lookup via connected UDP socket; a full-tunnel VPN that also carries the default route is allowed), `dialable()`, router port mapping (crab_nat PCP/NAT-PMP then igd-next UPnP; only used if external IP is global; released at shutdown). webjetd.toml `[nat]`: skip_tunnels, exclude_interfaces, allow_interfaces (globs), exclude_cidrs, port_mapping.
- `crates/webjet-net/src/kcp.rs`: K_PUNCH datagrams now carry type (1 PING / 2 PONG) + 16-byte token (= punch nonce); PING answered with PONG to source (rate-limited 2000/s); events go to `UdpEndpoint::punch_events`. Old padding-only PUNCH ignored.
- `crates/webjetd/src/punch.rs`: OFFER/OFFER/GO, checks to all candidates for 6 s (50 ms then 200 ms), peer-reflexive candidates learned from PINGs, port prediction (+96/−8 ports) when peer symmetric and we aren't, first PONG nominates; lower id dials, higher id after 1.5 s; blind parallel dial fallback; either side starts (higher id 5 s later); retry 15 s doubling to 5 min, immediately on RecordsChanged/HopDown. `punch::status` appears under `punch` in `local sessions`.
- `transport::nat_type` counts only observations from RELAY hops (a punched data-node hop's observed port can differ and made a cone NAT look symmetric).
- Test: `docker/nat-test.sh` (MODE=symmetric too) — two iptables NAT routers, public node without NAT, fake `wg0` VPN subnet that must not be used, loopback pings. Docker pitfalls found: `--internal` networks drop forwarded traffic leaving the subnet; .1 is the Docker gateway (routers use .2); NAT routers must DROP unsolicited WAN traffic in INPUT too, else a conntrack entry from the peer's early PING steals the port and MASQUERADE picks a new one.
