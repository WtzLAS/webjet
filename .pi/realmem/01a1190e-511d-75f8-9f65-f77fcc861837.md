Multicast/broadcast is on by default (user decision 2026-10), scoped only by policy, with IGMP/MLD snooping; limits default 50 pkt/s + 64 KiB/s; 255.255.255.255 from the physical NIC is not captured by the TUN path (documented limitation). Pure logic in `crates/webjet-core/src/multicast.rs`: `kind()` (Broadcast = 255.255.255.255 / IPv4 pool directed broadcast / 224.0.0.1 / ff02::1; Group otherwise; ff00/ff01 scopes excluded), `Report` encode/decode, `Budget` (pps+bps), `State` (sender reports REPORT_TTL 180 s, rotation; receiver `local` groups + `report_due` every 60 s; per-sender caps; echo digests over ECHO_WINDOW 1 s). I/O in `crates/webjetd/src/multicast.rs`: `outbound` (from `Dataplane::outbound` for non-unicast dst before gateway path; UDP from own overlay IP only, IPv6 link-local src rewritten), `recipients` (valid DATA nodes, policy me→peer, EndpointRecord feature `multicast`, `lookup_many` for unknown records), `inbound`/`deliver` (cryptokey check, policy, per-sender cap, pool broadcast rewritten to 255.255.255.255), `track()` inserts conntrack for the equivalent unicast flow so replies pass, `upkeep` (10 s tick, `multicast_limit` alarm), `watch_memberships` reads `platform::multicast_groups` (Linux /proc/net/igmp{,6}, macOS getifmaddrs FFI, Windows GetMulticastIpAddressTable; needs windows-sys feature Win32_NetworkManagement_Ndis). Frame types `ftype::MCAST = 13`, `GROUPS = 14`; limits `multicast_packets_per_sec` (0 = off, in `validate::ZERO_TURNS_OFF`) and `multicast_bytes_per_sec`; metrics `Counters.multicast_{tx,rx,limited,echo}`, `TunMetrics.multicast_{tx,rx}_packets` (schema → `webjet_multicast_packets_total`); `gossip::lookup_many` batches Lookups.

Capture (§9.5.2, added 2026-10 at user request, all three platforms, off by default): copies broadcasts/multicasts the host sends out its other interfaces (games bind 0.0.0.0 and broadcast to 255.255.255.255 out the LAN) into the overlay. Config: `MulticastConfig { capture: [string] }` appended as `TransportConfig.multicast`/`NodeConfig.multicast`; TOML `[multicast] capture = ["udp:19132"]` at network or node scope — a node's list replaces the network's, `[]` turns it off for that node; `View::capture_ports(node)`, `validate::multicast`; a node config holding only `multicast.capture` is not empty; `show` doesn't fill the section (old controllers — upgrade controllers first); control `node_config` effective `capture`. Pure logic: `CapturePorts` (UDP specs only; `NEVER_CAPTURED` = 67, 68, 137, 138, 1900, 3702, 5353, 5355); `captured()` — source must be one of the host's own LAN addresses, unfragmented, to limited broadcast, the LAN's directed broadcast (rewritten to 255.255.255.255) or IPv4 multicast; source rewritten to overlay address with port kept; `State::duplicate(digest, Origin::{Tun,Captured})` — same datagram sent both ways within DUPLICATE_WINDOW 500 ms goes out once. webjetd: `multicast::fan_out` shared by `outbound` (Tun) and `captured` (Captured); `crates/webjetd/src/capture.rs`: `start()` service (5 s config/interface check, `multicast_capture` alarm, retry after 60 s), reader threads → mpsc channel, `filter()` classic BPF generator + test interpreter. Linux: socket2 `Domain::PACKET`, `Type::DGRAM`, protocol **ETH_P_ALL** (ETH_P_IP sockets never see outgoing packets — first bug); filter PKTTYPE==OUTGOING, PROTOCOL==0x0800, UDP, not a fragment, dport ranges. macOS: `/dev/bpf*` per Ethernet/Wi-Fi interface with an IPv4 address (DLT_EN10MB), ioctls BIOCSBLEN/BIOCSETIF/BIOCGDLT/BIOCIMMEDIATE/BIOCSRTIMEOUT/BIOCSETF; `bpf_records()` parses `bpf_hdr` records. Windows: raw UDP socket bound to 127.0.0.1 (WinIPBroadcast trick); sees limited broadcasts only, not ones with sport==dport, ignores TTL 1. socket2 0.6 with feature `all` added to webjetd. Metrics: `TunMetrics.multicast_captured_packets` → `webjet_multicast_packets_total{direction="captured"}`; `Counters.multicast_duplicate` → limit_hits `multicast_duplicate`. Test: `docker/capture-test.sh`, 4 nodes; `raknet-lan -unbound`; iptables drops incoming eth0 udp:19132 to simulate separate LANs; without capture nobody sees worlds, with capture all worlds found within 3 s and RakNet play works; node override `[]` stops capture; both-ways datagrams carried once. Not tested on real macOS or Windows (cross-check only). Docs: architecture §9.5.1 + §9.5.2; configuration.md limits table, `[multicast]` section, node-scope table row, recipe "Play LAN games across the overlay".
