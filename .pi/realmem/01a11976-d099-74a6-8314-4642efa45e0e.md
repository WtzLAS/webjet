`docker/raknet-storm-test.sh` runs real RakNet (go-raknet v1.15.2) over Webjet on 5 nodes. The node program is `docker/raknet-lan/main.go`, its own Go module; the script builds it for Linux with host `go`, or with the `golang:1` image if Go is missing, and `docker cp`s it into `webjet:test` containers. Status goes to `/tmp/rak.txt` as `key value` lines, because the test image's python3-minimal has no json module. The run takes ~5 min; `KEEP=1` keeps the containers, `clean` removes them.

Phases and results (2026-10-08, default budget 50 copies/s + 64 KiB/s), wire bandwidth on eth0 over an idle baseline of ~10 KB/s for 5 nodes:
- A. 1 ping/s each: 11.7 KB/s, exactly 4 copies per ping, each received once.
- B. 20 RakNet connections all work.
- C. 20 pings/s: capped at ~47 copies/s per node, ~193 KB/s total, every world still seen thanks to rotation.
- D. naive rebroadcasting bridges: all rebroadcasts stopped as echoes, bandwidth same as A.
- E. mutating bridges: capped at ~47/s per node, ~122 KB/s total, gone as soon as the bridges stop.

For comparison, the EasyTier storm was 1.5 MiB/s.

Pitfall: budget assertions must use the measured elapsed time, not the nominal phase length.
