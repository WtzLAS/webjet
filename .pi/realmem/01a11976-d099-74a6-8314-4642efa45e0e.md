## Multicast/broadcast (on by default 2026-10, policy-scoped, IGMP/MLD snooping; limits default 50 pkt/s + 64 KiB/s; 255.255.255.255 from physical NIC not captured by TUN path — documented limitation)

Pure logic `crates/webjet-core/src/multicast.rs`: `kind()` (Broadcast = 255.255.255.255 / IPv4 pool directed broadcast / 224.0.0.1 / ff02::1; Group otherwise; ff00/ff01 excluded), `Report` encode/decode, `Budget` (pps+bps), `State` (sender reports REPORT_TTL 180 s, rotation; receiver `local` groups + `report_due` 60 s; per-sender caps; echo digests over ECHO_WINDOW 1 s).

I/O `crates/webjetd/src/multicast.rs`: `outbound` (from `Dataplane::outbound` for non-unicast dst before gateway path — must also check `multicast::is_pool_broadcast`, since pool directed broadcast like 10.7.255.255 looks unicast to `packet::is_unicast` and would hit `route()` → no_route + ICMP; UDP from own overlay IP only, IPv6 link-local src rewritten), `recipients` (valid DATA nodes, policy me→peer, EndpointRecord feature `multicast`, `gossip::lookup_many` for unknown records), `inbound`/`deliver` (cryptokey check, policy, per-sender cap, pool broadcast rewritten to 255.255.255.255), `track()` conntrack for equivalent unicast flow, `upkeep` (10 s tick, `multicast_limit` alarm), `watch_memberships` reads `platform::multicast_groups` (Linux /proc/net/igmp{,6}, macOS getifmaddrs FFI, Windows GetMulticastIpAddressTable; needs windows-sys feature Win32_NetworkManagement_Ndis). Frame types `ftype::MCAST = 13`, `GROUPS = 14`; limits `multicast_packets_per_sec` (0 = off, in `validate::ZERO_TURNS_OFF`), `multicast_bytes_per_sec`; metrics `Counters.multicast_{tx,rx,limited,echo}`, `TunMetrics.multicast_{tx,rx}_packets` (schema → `webjet_multicast_packets_total`).

**Capture (§9.5.2, added 2026-10, all three platforms, off by default):** copies broadcasts/multicasts the host sends out its other interfaces (games bind 0.0.0.0, broadcast 255.255.255.255 out LAN) into the overlay. Config `MulticastConfig { capture: [string] }` as `TransportConfig.multicast`/`NodeConfig.multicast`; TOML `[multicast] capture = ["udp:19132"]` at network or node scope — node list replaces network's, `[]` disables per node; `View::capture_ports(node)`, `validate::multicast`; node config with only `multicast.capture` is not empty; `show` doesn't fill the section (upgrade controllers first); control `node_config` effective `capture`. Pure logic: `CapturePorts` (UDP only; `NEVER_CAPTURED` = 67, 68, 137, 138, 1900, 3702, 5353, 5355); `captured()` — src must be host's own LAN address, unfragmented, to limited/directed broadcast (directed rewritten to 255.255.255.255) or IPv4 multicast; src rewritten to overlay address, port kept; `State::duplicate(digest, Origin::{Tun,Captured})` — same datagram both ways within DUPLICATE_WINDOW 500 ms sent once. webjetd: `multicast::fan_out` shared by `outbound` (Tun) and `captured` (Captured); `crates/webjetd/src/capture.rs`: `start()` service (5 s config/interface check, `multicast_capture` alarm, retry 60 s), reader threads → mpsc, `filter()` classic BPF generator + test interpreter. Linux: socket2 `Domain::PACKET`, `Type::DGRAM`, ETH_P_ALL (ETH_P_IP sockets never see outgoing packets — first bug); filter PKTTYPE==OUTGOING, 0x0800, UDP, not fragment, dport ranges. macOS: `/dev/bpf*` per Ethernet/Wi-Fi iface with IPv4 (DLT_EN10MB), ioctls BIOCSBLEN/BIOCSETIF/BIOCGDLT/BIOCIMMEDIATE/BIOCSRTIMEOUT/BIOCSETF; `bpf_records()` parses `bpf_hdr`. Windows: raw UDP socket bound 127.0.0.1 (WinIPBroadcast trick); limited broadcasts only, not sport==dport, ignores TTL 1. socket2 0.6 feature `all` in webjetd. Metrics: `TunMetrics.multicast_captured_packets` → `webjet_multicast_packets_total{direction="captured"}`; `Counters.multicast_duplicate` → limit_hits `multicast_duplicate`.

## E2E tests

**`docker/multicast-test.sh`** (image `webjet:test`; build `docker build --target test -t webjet:test .`; `KEEP=1` keeps containers, `clean` removes): ctl-01 + g-1/g-2/g-3 (`tag:game`) + o-1 (`tag:office`), subnet 172.30.8.0/24; uses `docker/mcast.py` (listen/send/pong); test image includes python3-minimal (no json module). Passed 2026-10-08, ~1.5 min. Capture test **`docker/capture-test.sh`**, 4 nodes; `raknet-lan -unbound`; iptables drops incoming eth0 udp:19132 to simulate separate LANs; without capture nobody sees worlds, with capture all worlds found within 3 s and RakNet play works; node override `[]` stops capture; both-ways datagrams carried once. Not tested on real macOS/Windows (cross-check only).

**`docker/raknet-storm-test.sh`** runs real RakNet (go-raknet v1.15.2) over Webjet on 5 nodes. Node program `docker/raknet-lan/main.go`, its own Go module; script builds it for Linux with host `go`, or the `golang:1` image if Go is missing, and `docker cp`s it into `webjet:test` containers. Status to `/tmp/rak.txt` as `key value` lines. Run ~5 min; `KEEP=1` keeps containers, `clean` removes.

Storm phases and results (2026-10-08, default budget 50 copies/s + 64 KiB/s), wire bandwidth on eth0 over idle baseline ~10 KB/s for 5 nodes:
- A. 1 ping/s each: 11.7 KB/s, exactly 4 copies per ping, each received once.
- B. 20 RakNet connections all work.
- C. 20 pings/s: capped ~47 copies/s per node, ~193 KB/s total, every world still seen thanks to rotation.
- D. naive rebroadcasting bridges: all rebroadcasts stopped as echoes, bandwidth same as A.
- E. mutating bridges: capped ~47/s per node, ~122 KB/s total, gone as soon as the bridges stop.

For comparison, the EasyTier storm was 1.5 MiB/s.

## Pitfalls

Budget assertions must use measured elapsed time, not nominal phase length. `webjetctl network node enroll --tags` needs `tag:` prefix. Ping-wait loops need `sleep 1` ("host unreachable" returns instantly while routes come up). Linux delivers a host's own broadcasts back to it, so reflector/repeater scripts must skip their own source address or loop locally at 46k/s. A loop mutating its payload dies once the budget drops one copy (each reflection chains on the previous), not sustained at budget rate.
