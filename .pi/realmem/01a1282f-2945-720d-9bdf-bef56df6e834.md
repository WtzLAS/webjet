Changed after v0.12.0 (2026-10-11), prompted by edges in the live network keeping only 2 home relays: three cloud controllers advertised only random reflexive KCP ports and had no 6969 listener.
- `Config::load` (crates/webjetd/src/config.rs) now uses `try_exists()`. A missing file still means defaults, but an inaccessible one (e.g. `/etc/webjet` the `webjet` user can't enter) fails with "can't access …". Before this the agent silently ran with defaults: no `[listen]` or `[[public]]`, random UDP port, no TLS listener. `webjetd` main.rs and `webjetctl local` (`agent_config`) only report "not found" when `try_exists` returns `Ok(false)`. Test: `config::tests::a_missing_file_means_defaults_an_unreachable_one_an_error`.
- `health::check_listen` (every 10 s in `health::run`) raises the `not_listening` warning alarm when this node is a relay or controller, has no `[listen]` tls/kcp/anytls, and has no router port mapping. The pure logic is in `listen_alarm(core, &Listen, mapped)`, tested by `health::tests::relays_and_controllers_must_listen`.
- Docs updated: architecture §19.7 alarm table, and docs/configuration.md (webjetd.toml intro and the `[listen]` section).
