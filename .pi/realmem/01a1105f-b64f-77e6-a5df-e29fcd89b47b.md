Ops guide 4.1 is implemented (commit abecacd):
- `webjetctl local controller force-new-cluster --reason R [--min-version N]` and `webjetctl local controller restore --from FILE --reason R [--min-version N] [--replace]`. Both run with the agent stopped (`recovery::ensure_stopped` checks the control socket) and live in `crates/webjetd/src/controller/recovery.rs`.
- Mechanism: a new `EntryPayload::ForceNewClusterEntry {voter, learners, grant_control, reason}` (webjet.fbs) is appended offline via `Raft::append_offline(term, bytes)`, in a new term with a self-vote. `classify_entry` maps it to `ConfChange::Set`. `Machine::prepare` refuses it; only `Machine::prepare_offline` builds it. If the log is below min_version (default: the store's high_water, and for restore at least the snapshot index), the log is replaced by a snapshot at that index (`Storage::clear_log`), so new heads sit above the old versions. Files are chowned to the data dir owner.
- force-new-cluster replays the whole log (including uncommitted entries) and keeps the old members as learners. restore needs a node that is valid in the snapshot and on the same genesis. It sets `NodeFile.restored_controller`, so the agent starts the controller role before its tree shows the control role (cleared once it does); grant_control gives the role.
- Export: `webjetctl network controller snapshot --out F`. An admin-signed `SnapshotRequest` (msg type 29) goes to the control cmd `snapshot` (Access::Signed) → `Controller::export_snapshot` or RPC `GetSnapshot`/`SnapshotReply` (wire.fbs; listed in `compression::secret_rpc`). The file is sealed with WEBJET_BACKUP_PASSPHRASE (`seal`, magic WJE1).
- Tests: recovery unit tests use `testutil::Cluster::log()` (encoded applied entries); `docker/runbook-test.sh` covers 3.8 / 4.1 step 3 / step 4.
- Pitfall: a non-member controller reports raft role `Learner`, so wait on the leader's `learners` list, not `role: Learner`.
