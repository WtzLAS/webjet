Fix (2026-10) for "accept_real_ip turned on + target restart, app still sees overlay IP": the ingress decided real_ip only at flow start, and live flows (UDP game clients) were refreshed forever.
- `Proxy::reevaluate` (crates/webjetd/src/proxy.rs, runs every refresh ~10 s) now also closes ingress flows whose source (client's vs translated: `info.client.src == k.flow.src`) doesn't match `rule.real_ip && target is the node && target's EndpointRecord has FEATURE_REAL_IP`; unknown record → keep.
- TCP resets (`packet::tcp_reset(orig, reply)` in webjet-core packet.rs; rate limit `Proxy.reset_bucket` 100/s burst 200; `Proxy::reset_for` skips non-TCP, RST, bare SYN): ingress `from_client` non-SYN segment with no flow → RST written to tun from proxy address to client; target `to_target` Ct::Invalid → RST sent back to the ingress in a PROXY frame (from_peer forwards it to client only if ingress still tracks the flow).
- Tests: `ingress_closes_flows_when_the_target_changes_real_ip`, `target_resets_segments_of_unknown_flows`, `packet::tests::tcp_resets`; Docker: `docker/realip-test.sh` (python server on node-b outside webjetd + client keeping UDP flow/TCP conn alive across restarts; checks on→client IP, off→ingress IP).
- After a target agent restart the ingress keeps the stale KCP hop ~15 s ("hop down" then "hop up"); new flows time out in that window — tests must wait for ping to the target before checking.
